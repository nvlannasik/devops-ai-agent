# devops-ai-agent

Slack bot + agentic loop for incident investigation & RCA. Part of a 3-repo system:
`devops-ai-agent` (this), `devops-mcp-server` (tools), `llm-worker` (private-LLM SQS consumer).

**Read `MEMORY_BANK.md` before changing the agentic loop, memory, SQS dispatcher, or
incident memory** — it holds the architecture, design decisions, and bugs already fixed.
Deeper design in `docs/` (e.g. `DESIGN_guarded_remediation.md`). Quality bar for the whole
stack — scenarios, scoring, rollout — in `docs/BENCHMARK_agent_stack.md`.

## Commands
- Build: `npm run build` (tsc → `dist/`)
- Test: `npm test` (`node:test` + tsx, zero extra deps)
- Dev: `npm run dev`
- DB migrate: `npm run migrate` (dev) / `npm run migrate:prod` (prod)
- **Node 24 required.** Default shell node is v14 — use `~/.nvm/versions/node/v24.16.0/bin` on the PATH.

## Conventions
- TypeScript ESM (NodeNext). Test files `*.test.ts` are excluded from the build.
- Match surrounding style. Prefer stdlib / already-installed deps over new dependencies.

## Gotchas (see MEMORY_BANK.md for the full list)
- **Follow-up mode:** `markRcaSent` + the `[FOLLOW-UP ...]` prefix keep the LLM out of RCA format. Do not remove.
- **History trimming:** always use the pairing-aware `trimToWindow()` — never a blind `slice`/`splice` (splits `tool_use`/`tool_result` → Anthropic 400).
- **Every ceiling in the loop must end in an answer, never an apology** (`forcedFinalAnswer()` in `agent/index.ts`). Two ceilings exist and only one used to be wired: the tool budget (conversation mode, `MENTION_TOOL_ROUNDS`) forced a final tool-free turn, while the alert path passes no budget — `maxToolRounds` is `Infinity` — so it ran all 10 iterations of tools, fell out of the `while`, and returned "try a more specific query" into an on-call thread that had never been shown a finding. Ten rounds of evidence, discarded. The ceiling now fires at `MAX_ITERATIONS - 1` to keep one turn in hand. The budget notice wins when both apply: it carries conversation mode's "do NOT use the RCA format" rule, and the ceiling notice deliberately carries no format rule at all because on the alert path the answer IS the RCA. `final-answer.test.ts` pins both.
- **The group alert text is the investigation's input, not just a Slack card** (`correlation/buildGroupAlertText`, posted at `app/index.ts:384` and passed to `investigate()`). So its errors are the agent's errors: `alerts[0].annotations` used to stand in for the group whenever a rule templates its subject into the text (Alertmanager's `commonAnnotations` is empty the moment two members differ), and the pod count was the **alert** count — "4 affected pods" for two, because the rule fires per `(pod, status)`. Now: `commonAnnotationsOf()` is the intersection, a member's text that cannot speak for the group is labelled `Summary (1 of 4)`, `distinctSubjects()` adds a `Services (N)` line (walks `service → deployment → workload → app`; `job` is excluded, it is the scrape job), and pods are de-duplicated. `distinctSubjects()` also feeds `delegationHint()` — a group spanning two services is two candidate causes **stated by the payload**, which is the deterministic trigger for delegation after the model never once pulled it on its own.
- **Sub-agent delegation is off by default and OFF means unregistered** (`agent/subagent/`, `SUBAGENT_ENABLED`). The whole point of the flag is that OFF is the baseline ON gets compared against, so the tool must not be registered-and-refused: the tools array is cached as one block and counts against the context budget, so a present-but-unusable tool moves both. A delegate is `runInvestigation()` again with `maxIterations`/`deadline`/`depth` options — **never a second loop**, because the `[WRITE]` filter, the namespace scope lock, the log fan-out cap and `forcedFinalAnswer()` all live in that one. Delegate calls are split out of the round *before* the scope lock (they carry no namespace, so a first round of only delegates would lock the scope to the empty set and disable the lock for the run). `DELEGATION_SECTION` in `prompts/system.ts` is appended to the system prompt when the flag is set — the first deployed build shipped the tool with an unlimited budget and the model never called it, because one description among fifty is not where strategy forms; it is conditional but still one constant string per process, so the ephemeral cache block is intact, and it keys on the **tool list** rather than the flag because the two disagree by design. Delegation is offered only to a run with an **infinite** tool budget (`offersDelegation()`) — the alert path and an explicit investigation request; on a 2-round mention one delegate spends half the budget and 60s of the parent's clock and cannot pay for itself. Depth is fixed at 1 and stated separately, delegates run in parallel with a deadline 60s inside the parent's, and every refusal is a synthesized `tool_result` — an unanswered `tool_use` is a 400. Full rationale in `MEMORY_BANK.md`.
- **A thread's conversation and its playbooks must have the same lifetime.** `threadSkills` was an in-process `Map` while `conv:` lived in Redis, so a rollout returned a live thread with its full history and none of its playbooks — a latency follow-up answered without the latency playbook, and nothing in the log said so. Playbook **names** now persist under `skills:<threadId>` on the conversation's TTL (`ConversationMemory.getSkills/setSkills`, dropped by the same `clear()`), rehydrated once per process per thread and resolved against the LIVE registry by `resolveSkillNames()` — a skill deleted from `prompts/skills/` must not come back. Paired with it: `buildMentionMarker()` restates the thread's alertname and namespace on every mention, because `history[0]` is pinned but by round two it is one sentence at the far end of the window against a fresh tool result — that is how a `sample-apps` question came to query `default`. The clause **anchors, it does not forbid** (leaving is allowed against evidence the model must name); blocking belongs to the namespace scope lock, which separately disables itself whenever round one is all Prometheus/Loki — `namespacesOf()` reads a tool *parameter*, and those carry the namespace inside the query string. That hole is deliberately still open: closing it would also have stopped the agent following a hostname its logs named.
- **The dry-run guards the action; `agent/grounding/` guards the claim.** A model that invents a workload name (`order-service`, derived from a real Service `order-services-svc`) has its *proposal* refused by the mandatory dry-run — but the invented name still reaches Slack, `incidents.root_cause`, and the next investigation's recall block. `groundingGaps()` reports names an answer asserts that no `tool_result` in the thread returned; `SlackApp.warnIfUngrounded()` posts them as a **separate** thread message on both paths (appending to the RCA would break `buildRcaBlocks`/`extractSection`/`dashboard/rca.ts`). Candidates come from the backticks the RCA format already mandates for resource names, filtered to a DNS-1123 shape. The two boundary rules are load-bearing and opposed: a trailing `-` is grounded (a Deployment is only seen as its pods' prefix), a trailing letter or digit is not (`order-service` is a plain prefix of `order-services-svc`, and a substring test would confirm the invention from its own source). Evidence is `tool_result` blocks only — assistant text would let one hallucination confirm the next.
- **Lone surrogates are stripped at the wire, not at the producers** (`agent/llm/sanitize.ts`, called first in all three `LLMClient.chat()`s). Emoji are surrogate pairs and the RCA format is full of them, so any fixed-offset slice over model-written text can split one; `JSON.stringify` then emits a bare `\ud83d` and the server answers `400 ... no low surrogate in string`. The payload is identical on every backend, so this reads in the log as all three failing at once — it is one bug of ours, not three of theirs. Don't move the guard to the slices: there are five of them and the model can emit a lone surrogate on its own. `tools` are deliberately not walked (MCP-supplied, static, cached).
- **SQS:** the response queue is **shared** across replicas (one dispatcher per process, routed by `requestId`). Don't add per-pod queues.
- **`/alert` is async:** acks 200 immediately, investigates in the background. Don't re-block it.
- **System prompt** lives in `prompts/system.md` — editable without rebuild.
- **The core prompt is rendered, at `/prompt`, and the route is top-level on purpose.** The Context page used to show every skill's text in full while showing the core prompt's *size* only — the conditional half rendered and the unconditional, larger half hidden. It gets its own page for the reason `skillPage` exists (24k chars inline would bury the budget table). What it renders is `buildStaticSystemPrompt()`'s cached string — **the copy this process is holding**, read once at boot; `prompts/system.md` is editable without a rebuild, so git, the pod's disk and that string can all disagree, and only the last decides what the agent says. The page says so, because a reader who takes it for "what the repo holds" is reading the wrong thing at the moment it matters. **Not `/context/<something>`**: a skill's name is a filename and the skill route matches one segment under `/context`, so any reserved word there could be shadowed by a file someone adds to `prompts/skills` — a route that cannot collide beats a guard that has to remember to. `server.ts`'s `contextView()` builds the view for both routes, so the size the prompt page prints and the text it shows can never describe different strings. Checked before shipping it: the file carries no URL, credential, IP, email or channel id (the only `secret` match is the tool name `k8s_list_secrets`), and this dashboard already shows behind the same password every skill body and the full MCP tool inventory including which tools can write to the cluster.
- **Skills** (`prompts/skills/*.md`, loaded by `src/agent/skills/`) are prompt content selected
  per investigation: flat `name`/`description`/`when` frontmatter, hand-parsed (no YAML dep), body
  injected verbatim. `when` is `always` or a case-insensitive regex over the alert text. Boot
  throws on any malformation — `src/agent/skills/real.test.ts` loads the shipped directory, so a
  bad file fails `npm test` rather than a deploy.
- **Skills ride in the first user message, never in `systemPrompt`.** `llm/claude.ts:26-32` caches
  the whole system prompt as one ephemeral block; a system prompt that varied per investigation
  would be a full cache miss plus a rewrite at 1.25×. This also leaves the SQS contract untouched.
  `context/index.test.ts` asserts the prompt is byte-identical across different skill sets — that
  test is the guard, do not weaken it.
- **The context budget is the SMALLEST backend window**, resolved once at boot
  (`context/resolve-budget.ts`). The router picks a backend after the request is built, so the
  request has to fit the smallest one it might land in. Under pressure skills drop before history:
  history is evidence already gathered, a skill is advice.
- **Tool results are compacted at ingest** (`context/compact.ts`), so Redis holds the compacted
  form and the raw output is not recoverable. Only *consecutive* runs collapse — a global dedupe
  would merge two phases of an incident.
- **Incident memory = Postgres** (durable, `DB_*`), schema via `migrations/*.sql`. **Conversation memory = Redis** (24h cache). Don't conflate them.
- **Migrations run at pod startup** (`runMigrations` inside `DevOpsAgent.initialize()`), so a migration that fails is a pod that won't start. No `CREATE EXTENSION` — the similarity tier uses core `to_tsvector` for exactly this reason. Next file is `007_*.sql`.
- **Recall tiers are never flattened:** human-CONFIRMED (`incident_feedback`) > agent hypothesis (`incidents`) > "possibly related" (lexical similarity, `migrations/005`). Agent-produced verdicts must never be written to `incident_feedback` — that's the human tier.
- **Post-remediation verification is durable, not a timer** (`agent/remediation/verify.ts`, `migrations/006`): the check lives in Postgres and any replica claims it, `due_at` doubles as the lease. Three rules that cost live debugging to find: `k8s_list_pods` returns the pod **phase** (a CrashLoopBackOff pod is `Running` + `ready:false`, so readiness comes from `ready`); **`worse` = readiness falling only** — a rollout replaces the pod set, so restart deltas compare different pods; and `verdict` ≠ `status` in recall — `succeeded` just means the MCP call didn't error.
- **Alertmanager is the only source of truth for "what is firing"** — `alertmanager_get_alerts`, never Prometheus. `/api/v1/alerts` sees only rules Prometheus itself evaluates, so the moment a second evaluator exists (Loki Ruler, Kibana) it answers "nothing else is firing" while a log-based alert pages. Two places depend on it and must not drift apart: `alertState()` (`agent/remediation/verify.ts`), where **every status Alertmanager returns means still firing** — `silenced` most of all, since a human muted the notification, not the problem, and reading it as recovery lets someone close an incident by muting it; and the Blast Radius section of `prompts/system.md`, which must call it **unfiltered** (a namespace-scoped call can only confirm what you already know). `prometheus_get_alerts` is deleted server-side, so nothing can quietly fall back to it. The trade: an alert re-firing inside its `for:` window is still `pending` in the evaluator and invisible here — deliberate, and `decideVerdict` still refuses "recovered" while any pod is unready.
- **The mention path is gated by `worthProposing`** (`agent/remediation/proposal.ts`) — a read-only "status check" on a healthy cluster used to spend a **heavy** LLM call to be told `{"action": null}`. Propose when the reply is an RCA, the user asked for a change, or the answer carries fault evidence; skip otherwise and log why. **The alert path is NOT gated** (an alert firing IS the evidence). Deliberately asymmetric: a false positive costs one call that answers null, a false negative silently drops a fix — so widen the vocabulary, never tighten it. Two traps the tests caught: a healthy reply uses the same words a broken one does, so negations are stripped first and the keyword group must repeat (`"No alerts are firing and nothing is pending"` loses `firing` too) while stopping at "but"; and Indonesian verbs need stem matching (`\bperbaiki\b` can't match inside `diperbaiki`).
- **`toOpenAIMessages` (`agent/llm/openai-compatible.ts`)** must stay in sync with llm-worker's copy. Never flatten content blocks with `JSON.stringify` — a small model imitates the JSON it sees instead of calling a tool, and the output ends up in Slack.
- **Logging:** use `errDetail(err)` from `utils/logger`, not `${err}` (which drops the stack). Investigations run inside `withTrace(threadId, …)` so SQS requests carry `traceId` — that's the join key between the agent log, the llm-worker log, and the Slack thread.
- **Cluster/GitOps drift** returns `drift` from the worker instead of a plain refusal; the agent proposes `flux_reconcile` (restore what Git declares), still approval-gated.
- **Domain guardrail:** `## Scope of Work` in `prompts/system.md` + a scope clause in BOTH per-message markers (`[USER MESSAGE ...]` in `app/index.ts`, `[FOLLOW-UP ...]` in `agent/index.ts`). The prompt section alone doesn't hold on a small model — off-topic asks ("debug this code") got answered. Change all three together.
- **`max_tokens` vs `max_completion_tokens` is auto-detected per backend** (`openai-compatible.ts`): OpenAI's o-series/gpt-5 reject `max_tokens`; vLLM/DeepSeek/OpenRouter only know `max_tokens` — and both are plain `openai-compatible` entries in the same router, so one static choice is always wrong for someone. The client sends `max_tokens`, and on the 400 that names `max_completion_tokens` it flips and retries **once**, caching the answer on the instance (built once at boot). Deliberately different from llm-worker's `LLM_USE_MAX_COMPLETION_TOKENS` env flag: the worker talks to exactly one model, the router holds several.
- **LLM router:** failover is **up-only** (light → heavy, never the reverse) — a weak model fails by answering confidently, not by throwing. `router.test.ts` is what enforces it. Backends come from indexed `LLM_BACKEND_<N>_*` env vars validated at boot.
- **Dashboard auth** (`src/dashboard/auth.ts`, `DASHBOARD_PASSWORD`): one shared password, session in a signed cookie (`v1.<exp>.<hmac>`, key = `scryptSync(password)` so sessions survive restarts and work on every replica). Unset password = **503, never anonymous content**; `/healthz` stays open so the probe can't be taken out by a missing Secret. The port is still not routed by the Ingress — that is a second lock, not a replaced one. Design: `docs/DESIGN_dashboard_auth.md`. Still the one component exempt from "a config mistake stops the pod": a failed listener logs and the agent keeps investigating.
- **The RCA is Slack mrkdwn, not CommonMark** (`prompts/system.md`): `*single asterisk*` bold, `_underscore_` italic, `•` bullets, no `#` headings — a section is a whole line of bold. `src/dashboard/rca.ts` parses that by hand into per-section tables. Two rules there are load-bearing: **esc() before any markup** (so a tag can never be forged), and **degrade to the plain block** when it doesn't look like the template. Changing the template in `prompts/system.md` means changing the parser. **Severity/Confidence are promoted out of their sections** into a trailing verdict strip — but only when `oneLine()` agrees (one prose block, no newline, no fence); a model that argues its confidence keeps its panel.
- **The RCA page renders the Slack message's own shape: one column, section by section, unframed.** `rca.ts` emits one `<section class="rca-sec">` per section — label, then what it labels — and the rule between two of them replaces the blank line Slack separates them with (a blank line on a page is one leading of a paragraph and reads as a paragraph break). **Do not put the panel back on `.prose`.** A framed section has to be as wide as its widest neighbour while the text inside stops at its 68ch measure, and the difference was a measured 188px of empty card down the right of every paragraph — 21% of the card, on all five sections. **Nothing inside the RCA declares a width** — not `.rca`, not `.prose-text`, not `.rca-list`. The page's `--maxw` is the only measure, so the paragraphs, the dividers, the tables *and the fact strip above them* all end on one right edge. Capping the text alone is what produced the second complaint: at 62rem the prose stopped at 68ch/704px while the strip and the section rules ran to 944px, a measured 240px of ragged right. `views.test.ts` pins the no-inner-width rule for all five selectors. The tables then fill the column exactly (880px inner at 1280+) and still fit their frames at every width from 768 up.
- **The RCA's five sections are ranked by size, spaced by margin, and never by a blank line.** `.rca-head` is `--fs-lg` over prose at `--fs-md`: at `--fs-base` a heading was *smaller* than its own paragraph and Root Cause / Evidence / Ruled Out read as one run whatever the spacing. A blank line between paragraphs becomes a `<p>` (`proseText(text, fmt)` in `rca.ts`) — under `white-space: pre-wrap` it used to render as a literal empty line, one line tall, untunable; pre-wrap still holds the newlines *inside* a paragraph, which are the model's own. The degrade path calls the same helper with `esc` instead of `inlineMrkdwn`, so refused text gets the paragraphs and none of the markup. In `.rca td`, `overflow-wrap: anywhere` and `min-width: 12ch` on `td.primary` are **one decision**: `anywhere` is the only value that lowers a cell's min-content claim (with `break-word` the Evidence table measured 300px past its frame at 1024), and the price is a one-word label column collapsing to "Immedia/te" — the floor pays it. `.rca td em` re-casts the template's `_tool_name_` in `--font-data` (a Source cell is a tool name and an argument, not italic sans beside mono); prose keeps its italic.
- **The dashboard shows the post-remediation VERDICT, and it is not the same fact as the call's status.** `remediations.status = 'succeeded'` means the MCP call did not error; `remediation_checks.verdict` (`recovered | unchanged | worse | inconclusive`, migrations/006) is what the cluster did about it minutes later. The overview tile used to report the first and read as the second — a restart that returned 200 and fixed nothing scored as a success — so it now reports `recovered / (checks that reached a verdict)` and keeps the call counts in the sub-line. Three rules hold this together and each has a test: **a pending check is never in the denominator** (it is not a failure and not a success); **a NULL verdict stays its own bucket**, never coalesced into `inconclusive` (that would report an answer nobody gave); and **a row whose check has not concluded carries no tone at all** — falling back to the status put a green spine on an outcome nobody had measured, which is the exact masquerade this exists to stop. Status falls through only where no check will ever run (an unapproved proposal). `inconclusive` is deliberately absent from the `TONE` map: it means the evidence said nothing either way, and a colour would make that a finding. `worse` is `critical` and gets its own figure in the outcomes panel, shown even at zero.
- **Dashboard chrome is CSS-only.** The sidebar has no toggle and no stored state — every page but `/topology` ships zero client JS, so the rail responds to the viewport alone. **Chrome is a top bar plus a rail**: `body` is a two-row grid, the bar spans both columns at row 1, the rail is column 1 of row 2, and `.pane` **names no row at all** — auto-placement is correct in all three layouts, and `grid-row: 2` on it is what once dropped the sign-in card to the bottom of a one-row `body.bare` grid (`views.test.ts` pins it). The bar is stuck at 0 and the rail is stuck under it at `top: var(--topbar-h)`; CSS cannot read a sibling's height, so that token is the agreement between them and a literal in either place is a rail that slides under the bar. **The rail is grouped, badged and footed**: four destinations in two lists — Monitor (Overview, Incidents) and Agent (Topology, Context), because what the cluster did and what this process *is* are two different questions — each caption associated with its own `<ul>` via `aria-labelledby` so the grouping exists for a screen reader too. `Incidents` carries a badge of incidents firing **right now** (`queries.openIncidents()`, its own 60s cache, bounded by `NAV_COUNT_CAP`): deliberately NOT the overview's "Open" figure, which is bounded by the selected range — a badge that shrank when someone switched to 24h would report the control rather than the cluster. **Zero renders no badge** ("nothing is on fire" is what an absent badge says) and **`undefined` renders no badge either** — a page that could not read the count must not assert zero. The session note moved from the top bar to the rail foot, above a hairline, and sign out gives up a weight step so a reader scanning four destinations does not find five. Nothing in the rail dims itself with `opacity`: `--text-dim` at .75 alpha measures 3.50:1 on the light surface, under the 4.5:1 that 11px text needs — a caption earns its rank from size, tracking and case, which cost no contrast. **Three widths, three answers.** Above 60rem the rail is a column. Between 46 and 60rem it lies down as a bar: group captions hidden (a caption inline between items reads as another destination) and the lists laid out in a row — they stay lists, so the grouping survives for assistive tech. Below 46rem it is an **off-canvas drawer behind a burger**, which replaced an icons-only bar that clipped every label at a measured 38rem; a rail that has gained group captions and a badge cannot survive having its words taken out.
  The drawer is a **checkbox + `<label>`**, the same script-free disclosure the topology zoom control runs on. The objection that ruled out a *collapse* toggle does not apply and the difference is worth keeping straight: a collapse toggle is a preference and would have to survive navigation, which a server-rendered page cannot do — a drawer is transient, and closing when you pick a destination is exactly right. The input carries the accessible name and the label carries none (naming both announces it twice); what this pattern cannot give is `aria-expanded`, which is the price of the CSP. The input must PRECEDE the scrim and the rail — `~` only reaches forward. Closed, the drawer is `visibility: hidden` and not merely translated away, or a keyboard lands in a menu it cannot see; `visibility` is transitioned at zero duration and delayed on the way out so the slide is actually seen. The page behind still scrolls while it is open — stopping that needs a script, and the scrim makes it moot.
**`layout()` takes an options object (`Chrome`), not positional arguments** — it had six and the badge would have been a seventh. The bar's right-hand slot is `layout()`'s `tools` argument — page-level controls (today only the overview's time range), never destinations, which are the rail's. **`.seg` is one component with three mechanisms**: the time range is links (`aria-current`), the topology scale control is radio labels (`:checked ~`), and the live pan/zoom toolbar is buttons. The markup differs because the mechanism has to; the look must not, so all three share one rule. Icons are hand-written inline `<svg>` (`default-src 'none'` blocks icon fonts and sprite `<use>` both). The icons-only breakpoint clips the label (`clip-path: inset(50%)`) instead of removing it, keeping it in the accessible name. `main`/`footer.bottom` need `width: 100%` **and** `min-width: 0`: as flex items with `margin: 0 auto` they otherwise take fit-content and scroll the whole page sideways on a phone.
- **Vertical rhythm belongs to the page, in three steps, and `main > * + *` is what states it.** It used to belong to the *headings*: a section heading carried its own top margin, so any two blocks a heading separated were spaced and any two it did not were **touching** — the KPI shelf sat edge to edge with the hero, and the token shelf with the backend table, both being one section holding two blocks. The scale is `--sp-4` (16px) between peer items in a grid, `--stack` (24px) between stacked blocks of different kinds, and the `h2` margin (32px+) between sections; each step has to clear the one nested inside it, which is why the heading's floor was raised from `--sp-6` (it had become exactly `--stack`, so a section boundary said nothing the heading had not). The rule is a **minimum, not an addition** — adjacent siblings' margins collapse, so it only ever raises a gap smaller than `--stack` and never stacks on top of a heading's larger one. Scoped to `main`'s direct children, so a document page (one `.doc` element) keeps the tighter lockups inside it, like an eyebrow against its own title. `.split` takes `--stack` rather than the grid step because its two panels hold different kinds of thing and become stacked blocks below 58rem. It is **`align-items: stretch`, stated rather than defaulted**: it was wrongly set to `start`, so each panel took its own content height and above 58rem the ring stood ~90px taller than the two-tile shelf beside it — a ragged row, visible only at wide widths because below 58rem there is one column. A stretched card is then taller than its contents, so `.split > .card` is a flex column and the figure block inside it takes the leftover room symmetrically (`margin-block: auto`) — the caption stays at the top, and the shorter card reads as generously padded rather than as one that ran out of content.
- **Dashboard sizing is fluid and container-scoped, not breakpointed.** `main` is a container (`container: page / inline-size`), and `.hero` / `.chart` declare their own — a media query can't size these, because the rail is a 13.5rem column above 60rem and a top bar below, so one viewport width means two content widths. Padding, gaps and `--fs-stat` are `clamp()`, not fixed steps. The stat shelf steps **4 → 2 → 1** (`@container page` 54rem / 26rem) and never `auto-fit` — an orphan tile reads as a bug. A shelf holds exactly four, or exactly two under the **`pair`** variant, which is a shelf inside a panel: it steps 2 → 1 and drops the card treatment, because the panel around it is already the card. **The hover lift is scoped to `[data-linked]`, and that is load-bearing rather than tidy**: a card that lifts under the pointer tells the reader it can be clicked, and only the two tiles with a real destination (Open and Resolved, into the filtered list) may make that promise. The anchor wraps the *label* and stretches over the tile with an `::after` — it cannot wrap the tile from outside, because `<a>` is not a permitted child of `<dl>` — and carries an `aria-label` naming the destination, since the visible label is one word. `views.test.ts` pins both the count and the scoping. `.split` is the two-panel row that holds them (2 → 1 at 58rem). **A shelf's sub-lines are all-or-nothing:** `.stat dd` is bottom-anchored, so one tile without a sub-line floats its value a line higher (`views.test.ts` pins it). `[data-tone]` (not `tr[data-tone]`) feeds **three** properties, and which one a rule reaches for is decided by what it paints: `--spine` is every **mark** (a row's leading bar, a badge's dot, a donut arc, a legend swatch), `--ink` is every piece of **text** in a tone (a badge's label, a delta's figure), `--tint` is the wash behind that text. Marks draw from a **separate `--mark-*` ramp**: a mark is a non-text graphic and needs 3:1, not 4.5:1, and one ramp cannot be both — `--warning: #8a5b00` is what an amber has to become to be readable as 11px type on white, and as a donut arc it read as brown. Light-scheme mark ratios against `--surface-raised`, all ≥3:1: critical 4.57, warning 3.60, info 4.12, ok 3.47. In dark the two ramps are identical, which is the finding rather than an oversight. `views.test.ts` pins the split. **The `TONE` map must map each tone name to itself** — `ok` was missing (only its synonyms `resolved`/`succeeded` were there), so `toneAttr("ok")` silently produced nothing and every good-news delta rendered untoned. **One measure, and it is `--maxw` (88rem).** The incident page used to drop to 58rem via `.pane:has(.prose)` — a reading measure for the RCA. It is **gone**: the rule capped the whole PAGE, so above ~1180px the fact strip, both record tables and the RCA all froze at 928px of `main` and the page stopped answering the screen (measured identical at 1440 and 1920). A measure that stops the figures growing to shorten the sentences is charged to the wrong block; if a line-length ceiling comes back it goes on the text, inside `.doc`. **Any page measure still has a floor of `step + 3`** — `main`'s content box lands ~3rem inside `--maxw`, so anything below it puts the container under the 54rem step and breaks the fact strip into two rows (`views.test.ts` pins it).
- **A document page is one `<div class="doc">`, not a run of loose children.** `detailPage` and `skillPage` both wrap their body in it. Laid straight into `<main>`, each block is its own full-width band sized only by its content — a measured `p.eyebrow` of 880×11 — with nothing declaring that they are one document. `.doc` is `width: 100%; min-width: 0` and **declares no measure**: the block takes the column, so both pages follow the screen (measured 1360 / 1176 / 760 / 468 at 1920 / 1440 / 1024 / 390). `statList(items, "facts")` marks the incident page's shelf: same component, but in the one-column step the tile lays caption and value on **one line** (identity, not figures — four stacked tiles were a third of a phone screen above the analysis).
- **The state column emphasises firing, not resolved.** It used to read backwards: `firing` wore the neutral badge (`--text-dim` on `--surface-2`) while `resolved` wore green, so in a column whose whole job is "which of these is still live" the live rows were the quietest thing in it. `stateBadge()` fixes it with **weight, not colour** — `data-live` gets full `--text` and a visible edge — because colour on this page belongs to severity and the row already states its severity one cell to the left.
- **An empty state is a panel, and wears its section's own glyph.** The dashed outline is gone: on this dashboard an empty state is almost never a hole (a window with no incidents is the good outcome, a fresh deployment is the ordinary first hour), and a dashed border says "this failed to load" where a real surface says "this is the answer". `empty(headline, next, icon)` takes the glyph as markup, unescaped, on the same contract as `Stat.icon`.
- **Colour is no longer held back from the chrome.** The old rule — colour reserved for severity, focus and where-you-are — is **gone by decision, not by drift**: links carry the accent, the rail's current item is a brand-tinted pill, section glyphs and KPI glyphs sit in brand-tinted chips, and the hero carries a low-alpha brand wash. What it is still held back from is the one place it was actually load-bearing: **`td.primary a` opts out** and stays `--text` with no underline until hovered, because that column is fifty links and fifty coloured links compete with the one critical row. Severity keeps its own vocabulary end to end, and **never rests on colour alone** — badges carry a dot *and* the word, rows carry the spine, the donut carries a legend of names and counts. The brand is a three-step ramp (`--brand-600` carries text and clears 4.5:1; 500/400 are for gradients, tints and glows only), and it inverts in dark mode so every rule reading `--brand-600` for text stays correct without knowing which scheme it is in.
- **Two faces, not three** (`styles.ts`): `--font-ui` for the interface and anything written in sentences, `--font-data` for what the system measured. The serif `--font-prose` on the RCA is **gone** — `font-src` is blocked, so it resolved to Iowan Old Style/Times and the RCA read as pasted in from elsewhere. Prose is marked as prose by its size and its leading (`--fs-md`/1.7), not by serifs and no longer by a panel or a measure of its own.
- **A wide table declares what it becomes on a phone**, because `.table-wrap`'s sideways scroll hides whichever columns come last with nothing pointing at them. `table(head, body, narrow)` in `html.ts` — three answers, and what chooses between the last two is **what the cells hold, not how many there are**: `"cards"` = the incident list only (rows become a 3-row grid placed **by cell name**, at 46rem); `"stack"` = values that are sentences — Evidence, Remediation, feedback, topology Inbound/Outbound — caption above the value (40rem); `"pairs"` = values that are all short — Token usage, Most recurring, LLM backends — the same stack with the caption beside the value via a **hanging indent** (`padding-left`/`text-indent`/`::before` width all 6rem), never flex or grid, which would split the inline flow. Captions always come from the cell's own `data-label`, so the layout names no column. `"pairs"` emits `data-stack data-pairs` **both** — the pairs CSS only overrides two declarations — and resets `text-indent` on every descendant, because it inherits and an `inline-block` child (a badge) re-applies it to its own first line. Opting out is a decision too: the MCP tools table is a name and a count, and stacking it would put the `<details>` tool list between the pair the row exists to show. That table is also **the only one laid out `table-layout: fixed`** (`table.caps` — the one table `table()` is handed a class for), and the exception must stay that narrow: every other table wants the auto algorithm, which divides the frame in proportion to what each column could use, and that is what balances the RCA's Evidence table at roughly 65/35 with no number written down anywhere. This one has a `<details>` in its first cell, and auto layout sizes from CONTENT — so opening a family inserted a list of tool names, raised that column's preferred width and re-divided the table, and the count column jumped sideways under the pointer on the very click meant to reveal something. Fixed layout reads its widths from the header row, which is why the `6rem` is stated on the `<th>`. Both change `display` on table elements, which **destroys the implicit table role** — hence the full `role="table"/rowgroup/row/cell/columnheader` chain, which only works if every level declares one (`headers()` / `cell()` exist for that). `td.when` drops `nowrap` in card mode: a nowrap cell doesn't shrink a `minmax(0,1fr)` track, it overflows it. Use `overflow-wrap: anywhere`, not `break-word` — only `anywhere` lowers min-content width. `breakable()` adds `<wbr>` at CamelCase humps, after `esc()` — **including the incident page's `<h1>`**, which used to print the name whole on the theory that a heading full of break opportunities reads as one. That is true of a soft hyphen, which renders a visible mark; a `<wbr>` renders nothing where the line fits and is taken in preference to a mid-word split where it does not. At 390px the heading read `KubernetesContainerOo / mKiller` while the same string in the table below broke at the hump. `overflow-wrap: anywhere` stays as the floor under a name with no humps at all. `<title>` keeps the plain `esc()` — a `<wbr>` there prints literally in the browser tab.
- **There are two charts, both server-rendered with no script.** `donutChart()` (`chart.ts`) draws the severity split with the circumference trick — a circle of radius `100/(2π)` has a circumference of exactly 100, so `stroke-dasharray: <share> <rest>` is an arc of *percent* and `stroke-dashoffset` rotates it; no arc maths, one `<circle>` per slice. The running offset accumulates from the **rounded** shares, or a sub-pixel gap opens at every boundary. `stroke-linecap` stays `butt` (a round cap overhangs its neighbour by half the stroke width). The ring is the glance and **the legend is the reading** — it prints every slice's name and count, which is what keeps severity off colour-alone.
- **The chart is a line chart: an SVG line over an HTML grid** (`lineChart()` in `src/dashboard/chart.ts`; `svg.ts` is deleted). The SVG holds the **line only** — every piece of text is HTML at the page's own sizes, because an SVG scales its text with its drawing and a `viewBox` can't be changed from CSS, which is what pinned a 4.3:1 letterbox with 4px captions on a phone. The `viewBox` is now a unit square stretched with `preserveAspectRatio="none"`, so the plot's height is a `clamp()`. **One `--h` per point, rounded once, feeds both renderers** (HTML dot at `bottom: var(--h)`, polyline vertex at `100 - h`) — round twice and the dot sits off its own line. Three rules keep drift at 0px, all found by measuring in headless Chrome: the plot grid has **no column gap** (vertices are at `(i+.5)/n` of the plot; a px gap moves every track centre); `.chart-line` is `height: calc(100% - 1.15rem)` and **never `auto`** (auto hands sizing back to the viewBox's ratio — the unit square draws itself square, 407px adrift at 768); and the dot's centring margin is on `bottom`/`left`, **not `top`** (an element offset from the bottom never uses a negative `margin-top` — a constant 4.5px float). `vector-effect: non-scaling-stroke` or the non-uniform stretch renders the line as a wedge. Percentage heights ride in `style="--h:…"` (permitted: the CSP is `style-src 'unsafe-inline'` with no `script-src`; the value is re-derived with `Number()` because Postgres returns `int8` as a string). Ticks are pre-marked `data-thin` **counting from the end** so the newest period never disappears, and survivors get `overflow: visible` or they render as `05-1`. The last point is `data-current` — unmarked, a partial week reads as a collapse. A single point draws no line; an all-zero series does, flat on the baseline.
- **Section glyphs go through `section()`, never a bare `<h2>`.** The helper wraps the icon and the label in `<span class="sec">` so they are one flex item — `h2`'s own `gap` is the distance out to the hairline, and between a glyph and its label it reads as two things. Every glyph is `stroke="currentColor" fill="none" aria-hidden focusable="false"`: no colour of its own (colour is reserved for severity, focus, and where you are) and no accessible name. `Stat.icon` is optional markup and must NOT be escaped; `Stat.label` still is. A glyph repeats only where the meaning does (wrench = remediation, speech = on-call, chip = model).
- **`/incidents` has a seventh filter with no field: `verdict`.** The form's six controls are a fixed 6 → 3 → 2 ladder and six is what divides evenly at every step, so a seventh control would re-cut every row of it. It is set by following a figure that already names it (the overview's "Made it worse") and shown as a **removable chip** while it is on — a filter nobody can see is a filter nobody can clear, and the × drops that one parameter and returns to page 1 because page 7 of the old result set is not a place in the larger new one. It goes through an allowlist of the four verdicts a checker can write: an unrecognised value is ignored rather than returning an empty page for a filter that cannot be true. In SQL it is `$7` in the shared `INCIDENT_WHERE` and the **only predicate that leaves the incidents table** — an `EXISTS` over `remediations JOIN remediation_checks`, never an outer join, because an incident with three remediations must appear once and a join would return it three times and break the page and the count in one stroke.
- **Every figure that names a set links to it.** Open and Resolved on the shelf, the recurring alert names, the donut's legend rows (`?severity=`) and Made it worse (`?verdict=worse`, and only when there are any — a link to an empty list is the dead end it was supposed to stop being). The hover lift is scoped to `[data-linked]` so nothing that stays put makes the promise.
- **`/incidents` pagination:** ten rows a page (`PAGE_SIZE` in `filters.ts`), fixed — no `pageSize` parameter, and nothing about paging in the filter form. Page size is not a filter, and a constant means no URL can widen the `LIMIT`. The pager sits below the table. The count is deliberately capped (`COUNT_CAP = 5000`, a `LIMIT` inside the subquery) — `5,000+` beats a full scan on a 3-connection pool. `hasMore` comes from the page's over-fetch, not the count, so Next stays right past the ceiling; `total` is floored at `offset + rows.length` because the two queries share no snapshot.
- **The dependency map draws structure and state from two different ramps, and carries its own key.** Edges, arrowheads and node outlines are `--mark-line` (3.63:1 light / 4.39 dark), NOT `--border-strong` (1.65 / 1.69): an arrow is nothing but its stroke, and in the light scheme a node box is nothing but its outline because `--surface` and `--surface-raised` are the same white, so the box has no fill contrast at all. The tell that this had been missed was that every mark carrying STATE already cleared 3:1 (the agent 17.82, the worker chip 6.17, not-configured 5.87) — the palette discipline had been applied to state and skipped for structure. **The cluster outline and the dot grid stay on `--border` deliberately**: a cluster groups boxes that position and a band label already group, and a dot grid is a texture; neither carries information, so neither has a bar to clear. `topoLegend()` states the vocabulary on the page (it was nowhere): its swatches use the same classes **and the same element** as the drawing — that is not pedantry, it drifted once, because the worker mark is the stroke of a *chip* and a `<path>` carrying `.topo-edge` as well came out grey at equal specificity. The key is conditional on what was actually drawn.
- **The map never scales below the width it was laid out for.** Its text lives inside the SVG (unlike the chart, which moved its type out to HTML for exactly this reason), so shrinking the drawing shrinks the type: at 390px the 11.5-unit labels rendered near 4.9px. `topologyDiagram` publishes `--topo-w` from its own `W` constant and the stylesheet floors `.topo` at it, so the number cannot drift from the layout; below that the map scrolls inside `.topo-view`. The floor is also what makes the frame clip, so `.topo-scroll-hint` says the rest is one drag away — revealed by a **container** query at 53rem, not a media query, because whether it overflows is a question about the content column, which is 13.5rem narrower with a rail beside it.
- **Dashboard CSP is per route** (`csp(nonce?)` in `src/dashboard/server.ts`). Only `/topology` passes a nonce and so gets a `script-src`; every other page has none, which is what keeps a missed `esc()` inert where LLM output is rendered. The interactive map's script (`topology-script.ts`) is inline under a **per-response** nonce — never `'unsafe-inline'`, and never a second script. It is progressive enhancement over the script-free radio scale control; don't delete the fallback. **Everything added since is still script-free and needs no CSP change**: the time range is three links (`?range=`), the segmented control is `aria-current`, and the self-refresh is `<meta http-equiv="refresh">`. The refresh is on the overview always and on `/incidents` **only when nothing is filtered and nothing is paged** — a reader who typed a filter is working, and reloading under them mid-row is worse than a stale page (`views.test.ts` pins both).
