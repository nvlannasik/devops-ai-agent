# devops-ai-agent — dashboard (`src/dashboard/`)

The read-only incident dashboard: server-rendered HTML with no client JS — except the two React Flow
maps, `/topology` and `/cluster`, which are the one thing here with a build step. Rules below are the ones
that cost live debugging to find; they were in the repo root's `CLAUDE.md` and moved down so
they load when you are actually working on this directory.

**One module per page, and the stylesheet in cascade order** (2026-10-21). `views.ts` is only a barrel
(`server.ts` and the tests import it); a page lives in `<area>-views.ts` and imports `parts.ts` (atoms: icons,
badges, `section`, `pager`) and `layout.ts` (the shell, sign-in, error page) — never the barrel, or ESM hands it a
half-initialised cycle (`views-split.test.ts`). `STYLES` is `styles/*.ts` concatenated in `styles.ts`; the order is the
cascade and `styles.test.ts` pins the exact bytes, so a new rule goes into the chunk for its area, and moving a
chunk is a visual change even though nothing errors.

**The build has three steps, not one.** `npm run build` = `tsc` (server) → `tsc -p
tsconfig.client.json` (typechecks the browser bundle; esbuild strips types without checking
them, so this is the only thing standing between `src/dashboard/client/` and unchecked code) →
`node scripts/build-client.mjs` (esbuild → `dist/public/topology.{js,css}` and `dist/public/cluster.js`). `npm run
build:client` is the last step alone. The Dockerfile needs `scripts/` and `tsconfig.client.json`
copied into the builder stage; the runtime stage already copies `dist/` whole.

Root `CLAUDE.md` still owns the agent loop, memory, SQS and remediation. `MEMORY_BANK.md` has the
long-form design record for both. The RCA's Slack mrkdwn template is a ROOT rule (it governs
`prompts/system.md`); `rca.ts` only parses what that template produces — change the template and
you change the parser.

## Gotchas

- **The look is "Atlas" (2026-11-10): an ink rail beside a light page, one indigo accent, and a theme the reader can choose.** Four things changed together and each has a rule behind it.
  - **The rail is ink in BOTH schemes, and it is legible through an "ink scope", not through rail-specific components.** `.rail` (always) and `.topbar` (below 60rem, where the bar is ink edge to edge) re-point the generic tokens — `--text`, `--text-dim`, `--surface-2`, `--border`, `--accent`, `--on-accent` — at the rail's own ramp (`--rail-text`, `--rail-dim`, `--rail-active`, `--rail-line`, `--rail-accent`). So the range control, the theme control and a nav link are the same rules on either ground; nothing below `:root` names a rail colour except the scope. Above 60rem there is no top bar at all (see the chrome entry below); the half-ink gradient it once wore is gone with it. The current destination is a lifted pill with its glyph on the accent — the label stays off the accent, because a violet word in a column of grey ones reads as a link. The Incidents badge is accent-filled now, not the critical tint: a red chip on ink read as an error in the chrome, and "how many are firing" is a count, with severity stated in the rows it leads to.
  - **The theme is a cookie and a route, never a script** (`theme.ts`). `/theme/(auto|light|dark)` sets `dash_theme` (HttpOnly, `SameSite=Lax`, one year; `auto` clears it) and 303s back to the Referer's path through `safeNext()`. The server's `send()` then runs every HTML response through `withTheme()` (`layout.ts`), which rewrites three fragments of the finished page — `<html data-theme>`, the `theme-color` meta, and which of the rail's three links is current. It is a post-pass rather than an argument because the theme belongs to the REQUEST and `layout()` is reached through some twenty page functions. `parseTheme()` is a two-value allowlist and is what keeps a cookie from writing markup. In CSS the dark values exist once (`styles/dark.ts`) and are emitted twice by `styles.ts` — under `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) }` and under `:root[data-theme="dark"]` — the one assembled place in the sheet, because the two blocks must be the same bytes. The maps read the same signal through `client/color-mode.ts` (`mapColorMode()` → React Flow's `colorMode`), or a reader who chose light on a dark system gets dark map controls on a light page.
  - **The stylesheet is a cached asset, not an inline `<style>`** (`stylesheet.ts`). Every page links `/assets/app.<hash>.css`; a page that used to carry ~165 KB of CSS is now its own markup. It and the font are served **before the password gate** with `cache-control: public, max-age=31536000, immutable` — the sign-in page needs them, and they hold nothing a visitor could not read from that page's source before. The map bundles stay behind the gate. The price is in the CSP entry below: `style-src` now names `'self'` on every page.
  - **One typeface is shipped, for display only.** `--font-display` is Space Grotesk (OFL 1.1, `fonts/`, a 22 KB latin variable woff2 embedded as base64 so there is no file to copy into the image) on the page title, the KPI figures, the hero count and the brand. Nothing a reader has to READ is set in it, so a browser that never fetches the file loses the character of four elements and none of the text.
  - **The overview opens with one filled tile** (`Stat.lead` → `data-lead`): Open, on the brand fill. At most one per shelf — two leads is no lead. Its hover rules live in the one `@media (hover: hover)` block in `styles/charts.ts` like every other hover.
  - **Found by looking, not by the tests — each is pinned in `views.test.ts` now.** (1) `text-overflow: ellipsis` on `.brand` did nothing: it is a flex container and the property acts on a block's own inline content, so at 390px the name was cut mid-letter. The ellipsis is on `.brand > span:last-child`. (2) The drawer stopped 72px short of an 844px screen: `align-self: start` on a `position: fixed` box makes `height: auto` shrink to content. It is `stretch` in the drawer block. (3) React Flow paints its own canvas (`#141414` in dark), a grey hole in an indigo-black page; `.react-flow { --xy-background-color: var(--surface); }` is the library's own hook. (4) Between 46 and 60rem the theme control is **placed** (`position: absolute`, top-right of the sticky bar) rather than flowed: beside sign out it took 180px from the nav and cost a fourth row of sticky bar (189px → 145px measured at 880px). Row one has the room at every width in the range — the Monitor list ends near 430px and the control starts at 518px at the narrow end — so a fourth Monitor destination is the thing that would break it.
- **The Context pages (redesign 2026-11-11).** `/context`: KPI shelf → a window card (the smallest backend's window as one `shareBar`: core prompt, tools, reserve, available — the question the page is opened for) → a Core prompt card whose `##` sections are chips linking to `/prompt#md-…` → the skills as a grid of cards (`.skill-grid`, `auto-fill` on purpose: a list of equal cards, not a fixed shelf), grouped Always / Matched, each with its trigger clamped to two lines and its size against `SKILL_MAX_CHARS` → Budget per backend. `/prompt` and `/context/<skill>` share `docPage()`: the `.detail` grid of the incident page, the text in the main column and, beside it, a facts shelf plus the document's outline. **Markdown headings carry ids now** (`md-<slug>`, numbered on a repeat) from one `slugger()` shared by `renderMarkdown` and `outlineOf`, which apply the same fence rule — a `#` in a PromQL block is a comment, not a heading — so an outline link always lands on its heading (`markdown.test.ts` pins both).
- **The core prompt is rendered, at `/prompt`, and the route is top-level on purpose.** The Context page used to show every skill's text in full while showing the core prompt's *size* only — the conditional half rendered and the unconditional, larger half hidden. It gets its own page for the reason `skillPage` exists (24k chars inline would bury the budget table). What it renders is `buildStaticSystemPrompt()`'s cached string — **the copy this process is holding**, read once at boot; `prompts/system.md` is editable without a rebuild, so git, the pod's disk and that string can all disagree, and only the last decides what the agent says. The page says so, because a reader who takes it for "what the repo holds" is reading the wrong thing at the moment it matters. **Not `/context/<something>`**: a skill's name is a filename and the skill route matches one segment under `/context`, so any reserved word there could be shadowed by a file someone adds to `prompts/skills` — a route that cannot collide beats a guard that has to remember to. `server.ts`'s `contextView()` builds the view for both routes, so the size the prompt page prints and the text it shows can never describe different strings. Checked before shipping it: the file carries no URL, credential, IP, email or channel id (the only `secret` match is the tool name `k8s_list_secrets`), and this dashboard already shows behind the same password every skill body and the full MCP tool inventory including which tools can write to the cluster.
- **Dashboard auth** (`src/dashboard/auth.ts`, `DASHBOARD_PASSWORD`): one shared password, session in a signed cookie (`v1.<exp>.<hmac>`, key = `scryptSync(password)` so sessions survive restarts and work on every replica). Unset password = **503, never anonymous content**; `/healthz` stays open so the probe can't be taken out by a missing Secret. The port is still not routed by the Ingress — that is a second lock, not a replaced one. Design: `docs/DESIGN_dashboard_auth.md`. Still the one component exempt from "a config mistake stops the pod": a failed listener logs and the agent keeps investigating.
- **The RCA page renders the Slack message's own shape: one column, section by section, unframed.** `rca.ts` emits one `<section class="rca-sec">` per section — label, then what it labels — and the rule between two of them replaces the blank line Slack separates them with (a blank line on a page is one leading of a paragraph and reads as a paragraph break). **Do not put the panel back on `.prose`.** A framed section has to be as wide as its widest neighbour while the text inside stops at its 68ch measure, and the difference was a measured 188px of empty card down the right of every paragraph — 21% of the card, on all five sections. **Nothing inside the RCA declares a width** — not `.rca`, not `.prose-text`, not `.rca-list`. The page's `--maxw` is the only measure, so the paragraphs, the dividers, the tables *and the fact strip above them* all end on one right edge. Capping the text alone is what produced the second complaint: at 62rem the prose stopped at 68ch/704px while the strip and the section rules ran to 944px, a measured 240px of ragged right. `views.test.ts` pins the no-inner-width rule for all five selectors. The tables then fill the column exactly (880px inner at 1280+) and still fit their frames at every width from 768 up.
- **The RCA's five sections are ranked by size, spaced by margin, and never by a blank line.** `.rca-head` is `--fs-lg` over prose at `--fs-md`: at `--fs-base` a heading was *smaller* than its own paragraph and Root Cause / Evidence / Ruled Out read as one run whatever the spacing. A blank line between paragraphs becomes a `<p>` (`proseText(text, fmt)` in `rca.ts`) — under `white-space: pre-wrap` it used to render as a literal empty line, one line tall, untunable; pre-wrap still holds the newlines *inside* a paragraph, which are the model's own. The degrade path calls the same helper with `esc` instead of `inlineMrkdwn`, so refused text gets the paragraphs and none of the markup. **The Severity/Confidence strip is a GRID, not a wrapping flex row.** As flex peers the two fields sized from their own content — Severity is one word (94px measured), Confidence is a word plus the sentence that explains it (647px) — so they sat side by side at wildly different widths with the labels landing nowhere near each other. They are a field LIST, so the labels take one column and the values another and the rows line up whatever either holds. The grouping `<div>` each pair needs for the `<dl>` is `display: contents`, or every pair is one cell and the columns never align. In `.rca td`, `overflow-wrap: anywhere` and `min-width: 12ch` on `td.primary` are **one decision**: `anywhere` is the only value that lowers a cell's min-content claim (with `break-word` the Evidence table measured 300px past its frame at 1024), and the price is a one-word label column collapsing to "Immedia/te" — the floor pays it. `.rca td em` re-casts the template's `_tool_name_` in `--font-data` (a Source cell is a tool name and an argument, not italic sans beside mono); prose keeps its italic.
- **The dashboard shows the post-remediation VERDICT, and it is not the same fact as the call's status.** `remediations.status = 'succeeded'` means the MCP call did not error; `remediation_checks.verdict` (`recovered | unchanged | worse | inconclusive`, migrations/006) is what the cluster did about it minutes later. The overview tile used to report the first and read as the second — a restart that returned 200 and fixed nothing scored as a success — so it now reports `recovered / (checks that reached a verdict)` and keeps the call counts in the sub-line. Three rules hold this together and each has a test: **a pending check is never in the denominator** (it is not a failure and not a success); **a NULL verdict stays its own bucket**, never coalesced into `inconclusive` (that would report an answer nobody gave); and **a row whose check has not concluded carries no tone at all** — falling back to the status put a green spine on an outcome nobody had measured, which is the exact masquerade this exists to stop. Status falls through only where no check will ever run (an unapproved proposal). `inconclusive` is deliberately absent from the `TONE` map: it means the evidence said nothing either way, and a colour would make that a finding. `worse` is `critical` and gets its own figure in the outcomes panel, shown even at zero.
- **Dashboard chrome is CSS-only.** The sidebar has no toggle and no stored state — every page but the two maps (`/topology`, `/cluster`) ships zero client JS, so the rail responds to the viewport alone. **Above 60rem the chrome is the rail alone** (layout pass, 2026-11-10): `body` is a one-row grid, the rail is a full-height column (`top: 0`, `height: 100vh`) headed by the brand and footed by the theme control and one `.rail-session` line (session note + text-only sign out), and `.topbar` is `display: none`. **Below 60rem the top bar exists** — burger and brand, nothing about the page — and `.rail .brand` is hidden so the name is not said twice; the brand markup is rendered in both places and CSS picks one. `.pane` **names no row at all** — auto-placement is correct in all three layouts, and `grid-row: 2` on it is what once dropped the sign-in card to the bottom of a one-row `body.bare` grid (`views.test.ts` pins it). Where the bar exists the rail is stuck under it at `top: var(--topbar-h)` (lying bar and drawer); CSS cannot read a sibling's height, so that token is the agreement between them. **A page's own controls live in its title row, not in the chrome**: `pageHead()` (`parts.ts`) renders eyebrow + `<h1>` + lede on the left and `.page-tools` on the right — the overview puts `liveNote()` and `rangeControl()` there — reusing the `.page-head` row the incident list and the cluster page already had. `layout()` takes no `tools` option any more. The eyebrow above a page title (`.doc > .eyebrow:first-child`, `.page-title > .eyebrow`) is accent-coloured and has no hairline, on every page. **The rail is grouped, badged and footed**: nine destinations in two lists — Monitor (Overview, Incidents) and Agent (Topology, Cluster, Alert memory, Conversation memory, Context, Benchmark, Harness), because what the cluster did and what this process *is* are two different questions — each caption associated with its own `<ul>` via `aria-labelledby` so the grouping exists for a screen reader too. `Incidents` carries a badge of incidents firing **right now** (`queries.openIncidents()`, its own 60s cache, bounded by `NAV_COUNT_CAP`): deliberately NOT the overview's "Open" figure, which is bounded by the selected range — a badge that shrank when someone switched to 24h would report the control rather than the cluster. **Zero renders no badge** ("nothing is on fire" is what an absent badge says) and **`undefined` renders no badge either** — a page that could not read the count must not assert zero. The session note sits in the rail foot, above a hairline, and sign out gives up a weight step so a reader scanning the destinations does not find one more. The foot also holds the **theme control** — three links (Auto, Light, Dark) in a `role="group"`, the current one marked `aria-current`; links to `/theme/<choice>`, not buttons, because there is no script to give a button something to do. Nothing in the rail dims itself with `opacity`: `--text-dim` at .75 alpha measures 3.50:1 on the light surface, under the 4.5:1 that 11px text needs — a caption earns its rank from size, tracking and case, which cost no contrast. **Three widths, three answers.** Above 60rem the rail is a column. Between 46 and 60rem it lies down as a bar: group captions hidden (a caption inline between items reads as another destination) and the lists laid out in a row — they stay lists, so the grouping survives for assistive tech. Below 46rem it is an **off-canvas drawer behind a burger**, which replaced an icons-only bar that clipped every label at a measured 38rem; a rail that has gained group captions and a badge cannot survive having its words taken out.
  The drawer is a **checkbox + `<label>`**, the same script-free disclosure the topology zoom control runs on. The objection that ruled out a *collapse* toggle does not apply and the difference is worth keeping straight: a collapse toggle is a preference and would have to survive navigation, which a server-rendered page cannot do — a drawer is transient, and closing when you pick a destination is exactly right. The input carries the accessible name and the label carries none (naming both announces it twice); what this pattern cannot give is `aria-expanded`, which is the price of the CSP. The input must PRECEDE the scrim and the rail — `~` only reaches forward. Closed, the drawer is `visibility: hidden` and not merely translated away, or a keyboard lands in a menu it cannot see; `visibility` is transitioned at zero duration and delayed on the way out so the slide is actually seen. The page behind still scrolls while it is open — stopping that needs a script, and the scrim makes it moot.
**`layout()` takes an options object (`Chrome`), not positional arguments** — it had six and the badge would have been a seventh. The bar's right-hand slot is `layout()`'s `tools` argument — page-level controls (today only the overview's time range), never destinations, which are the rail's. **`.seg` is links only, and used to be one component over three mechanisms** — the time range's links, the topology page's script-free scale control (radio labels, `:checked ~`) and its live pan/zoom toolbar (buttons). React Flow's own `<Controls>` replaced the last two, so the rule dropped `.seg label` and `.seg button`, which had stopped matching anything. The principle was good and is worth reinstating the moment a second mechanism needs this look: the markup may differ because the mechanism has to, the look must not. Icons are hand-written inline `<svg>` (`default-src 'none'` blocks icon fonts and sprite `<use>` both). The icons-only breakpoint clips the label (`clip-path: inset(50%)`) instead of removing it, keeping it in the accessible name. `main`/`footer.bottom` need `width: 100%` **and** `min-width: 0`: as flex items with `margin: 0 auto` they otherwise take fit-content and scroll the whole page sideways on a phone.
- **Vertical rhythm belongs to the page, in three steps, and `main > * + *` is what states it.** It used to belong to the *headings*: a section heading carried its own top margin, so any two blocks a heading separated were spaced and any two it did not were **touching** — the KPI shelf sat edge to edge with the hero, and the token shelf with the backend table, both being one section holding two blocks. The scale is `--sp-4` (16px) between peer items in a grid, `--stack` (24px) between stacked blocks of different kinds, and the `h2` margin (32px+) between sections; each step has to clear the one nested inside it, which is why the heading's floor was raised from `--sp-6` (it had become exactly `--stack`, so a section boundary said nothing the heading had not). The rule is a **minimum, not an addition** — adjacent siblings' margins collapse, so it only ever raises a gap smaller than `--stack` and never stacks on top of a heading's larger one. Scoped to `main`'s direct children, so a document page (one `.doc` element) keeps the tighter lockups inside it, like an eyebrow against its own title. `.split` takes `--stack` rather than the grid step because its two panels hold different kinds of thing and become stacked blocks below 58rem. It is **`align-items: stretch`, stated rather than defaulted**: it was wrongly set to `start`, so each panel took its own content height and above 58rem the ring stood ~90px taller than the two-tile shelf beside it — a ragged row, visible only at wide widths because below 58rem there is one column. A stretched card is then taller than its contents, so `.split > .card` is a flex column and the figure block inside it takes the leftover room symmetrically (`margin-block: auto`) — the caption stays at the top, and the shorter card reads as generously padded rather than as one that ran out of content.
- **Dashboard sizing is fluid and container-scoped, not breakpointed.** `main` is a container (`container: page / inline-size`), and `.chart` declares its own — a media query can't size these, because the rail is a 14.5rem column (`--rail-w`) above 60rem and a top bar below, so one viewport width means two content widths. Padding, gaps and `--fs-stat` are `clamp()`, not fixed steps. The stat shelf steps **4 → 2 → 1** (`@container page` 54rem / 26rem) and never `auto-fit` — an orphan tile reads as a bug. A shelf holds exactly four, or exactly two under the **`pair`** variant, which is a shelf inside a panel: it steps 2 → 1 and drops the card treatment, because the panel around it is already the card. **The hover lift is scoped to `[data-linked]`, and that is load-bearing rather than tidy**: a card that lifts under the pointer tells the reader it can be clicked, and only the two tiles with a real destination (Open and Resolved, into the filtered list) may make that promise. The anchor wraps the *label* and stretches over the tile with an `::after` — it cannot wrap the tile from outside, because `<a>` is not a permitted child of `<dl>` — and carries an `aria-label` naming the destination, since the visible label is one word. `views.test.ts` pins both the count and the scoping. **The overview's layout** (2026-11-10) is: title row → the four-tile state shelf → `.chart-card` (the window's count as a caption row above the full-width line chart; the old side-by-side `.hero` is gone) → **`.panels`**, three `.card`s that name themselves with `cardHead()` — Outcomes (severity `donutChart` over the `pair` shelf), Most recurring (`ol.rank`, scrolls inside its frame past ~4 rows, not on a phone), Token usage (`fmtCompact` total over the exact count, input/output `shareBar`, cache line) — → Recent incidents and Token usage by backend, each a `.card.flush` whose `.table-wrap` gives up its own frame. **Since 2026-11-11 the three panels are `.panels`, not three abreast**: abreast, a row was as tall as the recurring list and Outcomes / Token usage stood mostly empty, so those two stack in column 1 and Most recurring spans both rows of column 2 — its list is `height: 0; flex: 1 1 0`, so it adds nothing to the rows and scrolls inside the height the left column sets. One column below 38rem of page, in markup order (Outcomes, Token usage, Most recurring), and nothing scrolls inside anything there. Card titles are `<h2 class="card-title">`, not the mono section caption. **Layout pass 2 (same day) carried the card to the incident pages and People:** `panel(title, body, trailing)` (`parts.ts`) is a titled `.card.flush` around a table or an empty state, and Remediation, On-call feedback, Recent changes, Related alerts, LLM usage, the harness timeline and People's two tables use it. The **incident list is one card** — the filter form is the table's toolbar, the chip row sits under it, the pager is the card's foot. **The incident page (redesign 2026-11-11)** opens with `lifecycle()` — five steps (Fired, Remediation, Verified, On-call, Resolved) read off the recorded rows, each stated in words with a dot that only repeats it (`data-state` done | wait | warn | none; a verdict that is not `ok` in `TONE` is `warn`, never done). The fact shelf no longer repeats Fired/Resolved: it is Namespace, duration, Confidence and Investigation (LLM calls + tokens from `usage`). The side column adds `toc()`, "On this page", linking only the panels the page has (`panel(..., id)` gives them ids) and shown only where the side column exists. The RCA, Recent changes and Related alerts share the main column. The **incident page is a `.detail` grid**: the fact shelf (`<aside class="detail-side">`, first in the markup) and the RCA card (`.detail-main`); from `@container page (min-width: 58rem)` the facts are a sticky 18rem column on the right, drawn as one panel with hairline rows, and below it they are the four-up shelf above the RCA as before. Only the RCA shares the row — the five-column record tables stay full width. **Pass 3** did the rest: Topology's four tables, Context's three blocks (prose + table in one panel — a `<p>` in a flush card brings its own padding), Benchmark's By case / By configuration, Harness (Gates, nudge fates, LLM latency, a gate's Latest), the memory key page's three record tables and each Cluster namespace. `section()` now remains only where what follows is not a table: Benchmark's folds and run list, the memory recall text, the conversation transcript, Cluster's system-namespaces fold, and the prompt/skill pages. **A shelf's sub-lines are all-or-nothing:** `.stat dd` is bottom-anchored, so one tile without a sub-line floats its value a line higher (`views.test.ts` pins it). `[data-tone]` (not `tr[data-tone]`) feeds **three** properties, and which one a rule reaches for is decided by what it paints: `--spine` is every **mark** (a row's leading bar, a badge's dot, a share-bar segment, a legend swatch), `--ink` is every piece of **text** in a tone (a badge's label, a delta's figure), `--tint` is the wash behind that text. Marks draw from a **separate `--mark-*` ramp**: a mark is a non-text graphic and needs 3:1, not 4.5:1, and one ramp cannot be both — `--warning: #8a5b00` is what an amber has to become to be readable as 11px type on white, and as a chart mark it read as brown. Light-scheme mark ratios against `--surface-raised`, all ≥3:1: critical 4.57, warning 3.60, info 4.12, ok 3.47. In dark the two ramps are identical, which is the finding rather than an oversight. `views.test.ts` pins the split. **`TONE` must know every severity `parseSeverity` can write.** The assessed set is `critical | high | medium | low` (`agent/incidents/index.ts`, now exported so `views.test.ts` imports it rather than transcribing it) and three of the four were missing — so every incident the agent did not call Critical rendered a grey badge, a grey row spine and a grey bar segment, on a dashboard whose premise is that severity carries colour. Severity reaches `tone()` from three places (`severityBadge`, the row's `toneAttr`, the share bar's slice) and they all route through the one map. Collapsed at the BOTTOM (`high → warning`, `medium`/`low → info`): telling Critical from High at a glance is what an on-call page is for, while Medium and Low can share blue and be told apart by the word the badge always carries. **Nothing maps to `ok`** — green would assert a low-severity incident is good news, and this map is silent rather than wrong, the same reason `inconclusive` is absent. Note that `confidence` is ALSO `high|medium|low` and must never reach `tone()`: the same word means the opposite thing one field over, and a confident RCA painted amber would be the map lying. It is plain sub-line text today; keep it that way. **The `TONE` map must map each tone name to itself** — `ok` was missing (only its synonyms `resolved`/`succeeded` were there), so `toneAttr("ok")` silently produced nothing and every good-news delta rendered untoned. **One measure, and it is `--maxw` (88rem).** The incident page used to drop to 58rem via `.pane:has(.prose)` — a reading measure for the RCA. It is **gone**: the rule capped the whole PAGE, so above ~1180px the fact strip, both record tables and the RCA all froze at 928px of `main` and the page stopped answering the screen (measured identical at 1440 and 1920). A measure that stops the figures growing to shorten the sentences is charged to the wrong block; if a line-length ceiling comes back it goes on the text, inside `.doc`. **Any page measure still has a floor of `step + 3`** — `main`'s content box lands ~3rem inside `--maxw`, so anything below it puts the container under the 54rem step and breaks the fact strip into two rows (`views.test.ts` pins it).
- **A document page is one `<div class="doc">`, not a run of loose children.** `detailPage` and `skillPage` both wrap their body in it. Laid straight into `<main>`, each block is its own full-width band sized only by its content — a measured `p.eyebrow` of 880×11 — with nothing declaring that they are one document. `.doc` is `width: 100%; min-width: 0` and **declares no measure**: the block takes the column, so both pages follow the screen (measured 1360 / 1176 / 760 / 468 at 1920 / 1440 / 1024 / 390). `statList(items, "facts")` marks the incident page's shelf: same component, but in the one-column step the tile lays caption and value on **one line** (identity, not figures — four stacked tiles were a third of a phone screen above the analysis).
- **The state column emphasises firing, not resolved.** It used to read backwards: `firing` wore the neutral badge (`--text-dim` on `--surface-2`) while `resolved` wore green, so in a column whose whole job is "which of these is still live" the live rows were the quietest thing in it. `stateBadge()` fixes it with **weight, not colour** — `data-live` gets full `--text` and a visible edge — because colour on this page belongs to severity and the row already states its severity one cell to the left.
- **An empty state is a panel, and wears its section's own glyph.** The dashed outline is gone: on this dashboard an empty state is almost never a hole (a window with no incidents is the good outcome, a fresh deployment is the ordinary first hour), and a dashed border says "this failed to load" where a real surface says "this is the answer". `empty(headline, next, icon)` takes the glyph as markup, unescaped, on the same contract as `Stat.icon`.
- **Colour is no longer held back from the chrome.** The old rule — colour reserved for severity, focus and where-you-are — is **gone by decision, not by drift**: links carry the accent, the rail's current item is a lifted pill whose glyph takes the accent (the rail is ink — see the Atlas entry above), section glyphs and KPI glyphs sit in brand-tinted chips, and the hero carries a low-alpha brand wash. What it is still held back from is the one place it was actually load-bearing: **`td.primary a` opts out** and stays `--text` with no underline until hovered, because that column is fifty links and fifty coloured links compete with the one critical row. Severity keeps its own vocabulary end to end, and **never rests on colour alone** — badges carry a dot *and* the word, rows carry the spine, the donut carries a legend of names and counts. The brand is a three-step ramp (`--brand-600` carries text and clears 4.5:1; 500/400 are for gradients, tints and glows only), and it inverts in dark mode so every rule reading `--brand-600` for text stays correct without knowing which scheme it is in.
- **Three faces, and only one of them is shipped** (`styles.ts`): `--font-ui` for the interface and anything written in sentences, `--font-data` for what the system measured — both stacks of fonts the system already has — and `--font-display` (Space Grotesk, served from `/assets`) for the page title, the KPI figures, the hero count and the brand. The serif `--font-prose` on the RCA is **gone** and stays gone: it was a face the page named and could not deliver (`font-src` was blocked then), so it resolved to Iowan Old Style/Times and the RCA read as pasted in from elsewhere. That is the rule the display face is held to — a face this page names has to be a face this page delivers — and why it is display type only. Prose is marked as prose by its size and its leading (`--fs-md`/1.7), not by serifs and no longer by a panel or a measure of its own.
- **A wide table declares what it becomes on a phone**, because `.table-wrap`'s sideways scroll hides whichever columns come last with nothing pointing at them. `table(head, body, narrow)` in `html.ts` — three answers, and what chooses between the last two is **what the cells hold, not how many there are**: `"cards"` = the incident list only (rows become a 3-row grid placed **by cell name**, at 46rem); `"stack"` = values that are sentences — Evidence, Remediation, feedback, topology Inbound/Outbound — caption above the value (40rem); `"pairs"` = values that are all short — Token usage, Most recurring, LLM backends — the same stack with the caption beside the value via a **hanging indent** (`padding-left`/`text-indent`/`::before` width all 6rem), never flex or grid, which would split the inline flow. Captions always come from the cell's own `data-label`, so the layout names no column. `"pairs"` emits `data-stack data-pairs` **both** — the pairs CSS only overrides two declarations — and resets `text-indent` on every descendant, because it inherits and an `inline-block` child (a badge) re-applies it to its own first line. Opting out is a decision too: the MCP tools table is a name and a count, and stacking it would put the `<details>` tool list between the pair the row exists to show. That table is also **the only one laid out `table-layout: fixed`** (`table.caps` — the one table `table()` is handed a class for), and the exception must stay that narrow: every other table wants the auto algorithm, which divides the frame in proportion to what each column could use, and that is what balances the RCA's Evidence table at roughly 65/35 with no number written down anywhere. This one has a `<details>` in its first cell, and auto layout sizes from CONTENT — so opening a family inserted a list of tool names, raised that column's preferred width and re-divided the table, and the count column jumped sideways under the pointer on the very click meant to reveal something. Fixed layout reads its widths from the header row, which is why the `6rem` is stated on the `<th>`. Both change `display` on table elements, which **destroys the implicit table role** — hence the full `role="table"/rowgroup/row/cell/columnheader` chain, which only works if every level declares one (`headers()` / `cell()` exist for that). `td.when` drops `nowrap` in card mode: a nowrap cell doesn't shrink a `minmax(0,1fr)` track, it overflows it. Use `overflow-wrap: anywhere`, not `break-word` — only `anywhere` lowers min-content width. `breakable()` adds `<wbr>` at CamelCase humps, after `esc()` — **including the incident page's `<h1>`**, which used to print the name whole on the theory that a heading full of break opportunities reads as one. That is true of a soft hyphen, which renders a visible mark; a `<wbr>` renders nothing where the line fits and is taken in preference to a mid-word split where it does not. At 390px the heading read `KubernetesContainerOo / mKiller` while the same string in the table below broke at the hump. `overflow-wrap: anywhere` stays as the floor under a name with no humps at all. `<title>` keeps the plain `esc()` — a `<wbr>` there prints literally in the browser tab.
- **There are two charts, both server-rendered with no script.** `shareBar()` (`chart.ts`) draws parts of a whole — the severity split, and token input against output — as one horizontal bar: each segment is a `<span style="--w:<value>">` and `flex-grow: var(--w)` does the proportions, so the markup carries values, not percentages; a 3px `min-width` keeps one incident among hundreds from rounding to nothing, and a zero slice draws no segment but keeps its legend row. It replaced `donutChart()` on 2026-11-10, when the Outcomes panel was a third of a row and a ring had no square to sit in; **the donut came back for the severity split on 2026-11-11** once `.panels` made that card half a row. `donutChart()` (circumference trick: radius 100/(2π), `stroke-dasharray` = share, `dashoffset` = running sum of the ROUNDED shares) now draws each arc `GAP` (0.8 of 100 units) short so two slices in one tone — medium and low share the info blue — still read as two; offsets keep the full share. The share bar stays for the token split and the context window, whose shares are too lopsided for a ring. A slice takes its colour from `[data-tone]`, or `data-lead` (the accent) when it has no tone. The bar is the glance and **the legend is the reading** — it prints every slice's name and value (`display` overrides the text), which is what keeps severity off colour-alone.
- **The chart is a line chart: an SVG line over an HTML grid** (`lineChart()` in `src/dashboard/chart.ts`; `svg.ts` is deleted). The SVG holds the **line only** — every piece of text is HTML at the page's own sizes, because an SVG scales its text with its drawing and a `viewBox` can't be changed from CSS, which is what pinned a 4.3:1 letterbox with 4px captions on a phone. The `viewBox` is now a unit square stretched with `preserveAspectRatio="none"`, so the plot's height is a `clamp()`. **One `--h` per point, rounded once, feeds both renderers** (HTML dot at `bottom: var(--h)`, polyline vertex at `100 - h`) — round twice and the dot sits off its own line. Three rules keep drift at 0px, all found by measuring in headless Chrome: the plot grid has **no column gap** (vertices are at `(i+.5)/n` of the plot; a px gap moves every track centre); `.chart-line` is `height: calc(100% - 1.15rem)` and **never `auto`** (auto hands sizing back to the viewBox's ratio — the unit square draws itself square, 407px adrift at 768); and the dot's centring margin is on `bottom`/`left`, **not `top`** (an element offset from the bottom never uses a negative `margin-top` — a constant 4.5px float). `vector-effect: non-scaling-stroke` or the non-uniform stretch renders the line as a wedge. Percentage heights ride in `style="--h:…"` (permitted: the CSP is `style-src 'self' 'unsafe-inline'` with no `script-src`; the value is re-derived with `Number()` because Postgres returns `int8` as a string). Ticks are pre-marked `data-thin` **counting from the end** so the newest period never disappears, and survivors get `overflow: visible` or they render as `05-1`. The last point is `data-current` — unmarked, a partial week reads as a collapse. A single point draws no line; an all-zero series does, flat on the baseline.
- **The line chart draws every bucket, empty ones included, and a dense axis names every second one.** The series query used to `GROUP BY` the incidents alone, so a day nothing fired in was not on the axis at all: 09-04 sat beside 09-07 and the line drew a slope across quiet days (measured 2026-09-28). `generate_series` + `LEFT JOIN` now supplies the buckets — a 30d window is 31 points — and past `DENSE_AFTER` (16) the axis carries `data-dense`: every second label is hidden at every width, every fourth survives the narrow step (`data-thin4`), and the newest period is never the one hidden.
- **An incident LIST row shows the symptom, not the root cause** (`incidentSummary` in `rca.ts`). Since the Root Cause became a causal chain, printing `root_cause` whole put every step, every citation and every raw mrkdwn marker into one 300px row. The row takes step 1 without its label or `— _tool_` citation, renders it through `inlineMrkdwn`, and `td .summary` clamps it to two lines; the full RCA is one click away. The same audit moved a skill's description UNDER its name on `/context` (as a fourth column it sat past the frame's edge behind an unmarked scroll, because the `when` regexes are unbroken tokens that claimed the width — `td.trigger code` now breaks anywhere) and gave the Recommended Actions horizon floor `box-sizing: content-box` (under border-box its padding ate the 12ch and "Immediate" still broke).
- **Section glyphs go through `section()`, never a bare `<h2>`.** The helper wraps the icon and the label in `<span class="sec">` so they are one flex item — `h2`'s own `gap` is the distance out to the hairline, and between a glyph and its label it reads as two things. Every glyph is `stroke="currentColor" fill="none" aria-hidden focusable="false"`: no colour of its own (colour is reserved for severity, focus, and where you are) and no accessible name. `Stat.icon` is optional markup and must NOT be escaped; `Stat.label` still is. A glyph repeats only where the meaning does (wrench = remediation, speech = on-call, chip = model).
- **`/incidents` has a seventh filter with no field: `verdict`.** The form's six controls are a fixed 6 → 3 → 2 ladder and six is what divides evenly at every step, so a seventh control would re-cut every row of it. It is set by following a figure that already names it (the overview's "Made it worse") and shown as a **removable chip** while it is on — a filter nobody can see is a filter nobody can clear, and the × drops that one parameter and returns to page 1 because page 7 of the old result set is not a place in the larger new one. It goes through an allowlist of the four verdicts a checker can write: an unrecognised value is ignored rather than returning an empty page for a filter that cannot be true. In SQL it is `$7` in the shared `INCIDENT_WHERE` and the **only predicate that leaves the incidents table** — an `EXISTS` over `remediations JOIN remediation_checks`, never an outer join, because an incident with three remediations must appear once and a join would return it three times and break the page and the count in one stroke.
- **Every figure that names a set links to it.** Open and Resolved on the shelf, the recurring alert names, the severity legend rows (`?severity=`) and Made it worse (`?verdict=worse`, and only when there are any — a link to an empty list is the dead end it was supposed to stop being). The hover lift is scoped to `[data-linked]` so nothing that stays put makes the promise.
- **`/incidents` pagination:** ten rows a page (`PAGE_SIZE` in `filters.ts`), fixed — no `pageSize` parameter, and nothing about paging in the filter form. Page size is not a filter, and a constant means no URL can widen the `LIMIT`. The pager sits below the table. The count is deliberately capped (`COUNT_CAP = 5000`, a `LIMIT` inside the subquery) — `5,000+` beats a full scan on a 3-connection pool. `hasMore` comes from the page's over-fetch, not the count, so Next stays right past the ceiling; `total` is floored at `offset + rows.length` because the two queries share no snapshot.
- **The dependency map is React Flow, and it is split across four files for one reason: what is a CLAIM and what is a drawing.** `topology.ts` reads config into a `Topology`. **`topology-graph.ts` turns that into nodes and edges and is a plain `.ts` module with no React import** — because what it encodes is the claim the page exists to make (a `private-llm` backend hangs off `llm-worker`, everything else off the agent; tool families hang off the MCP server, not the agent), and a claim needs a test that runs under `npm test`. A `.tsx` inside the bundle is typechecked but never executed by `node:test`, so a rule written there is a rule nothing checks. `client/layout.ts` positions with dagre (`rankdir: LR`) and `client/nodes.tsx` draws. **The anchor is by `Node.id`, never by label** — matching the display string works until someone rewords it and then fails SILENTLY, drawing a plausible arrow from the wrong node; a missing anchor falls back to the agent, which is wrong-but-visible rather than a dropped edge. **A node's id IS its row's id** (`rowId()`, one definition, imported by both sides), so the card's link is `#${node.id}` and no second mapping can drift. Backend chips are mapped over the WHOLE list before the `viaWorker` split, or the two groups would number independently and half the links would point at the wrong row.
- **The map draws structure and state from two different ramps, and carries its own key.** Edges, arrowheads and node borders are `--mark-line` (3.63:1 light / 4.76 dark on `--surface`, 4.45 on `--surface-2`), NOT `--border-strong` (1.65 / 1.69): an arrow is nothing but its stroke, and in the light scheme a card is nothing but its outline because `--surface` and `--surface-raised` are the same white, so it has no fill contrast at all. The tell that this had been missed was that every mark carrying STATE already cleared 3:1 — the palette discipline had been applied to state and skipped for structure. React Flow ships its own light grey for all of this, so the overrides in `styles.ts` are not cosmetic. **The dot grid stays on `--border` deliberately**: it is a texture, it carries nothing, so it has no bar to clear. **State is two facts.** Not-configured is amber *and dashed*, never colour alone. The SQS edge is accented *and heavier* — it used to be accented *and animated*, the only moving thing on the page, on the argument that if every edge animated none of them would say anything. **Every edge animates now, by request (2026-09-02), so motion says the map is live and says nothing about a particular edge.** What that spent is one of four signals: the SQS hop is left with the accent stroke, the extra weight, the accent border on the card it reaches, and the legend row that names it. None of the three that remain is redundant — do not trade another one away. `prefers-reduced-motion` stops all of it, which now costs nothing at all, since the meaning had already moved onto the stroke. `topoLegend()` states the vocabulary on the page: its swatches use the same classes **and the same element** as the drawing — that is not pedantry, it drifted once, and it is why they are `<div class="topo-node …">` rather than the `<span>` that would read better. `.topo-swatch` overrides size and padding ONLY. The key is conditional on what was actually drawn.
- **`.topo-view` states a height, and React Flow renders nothing without one** (its canvas is absolutely positioned inside). The old SVG had the opposite problem — its text lived inside the drawing, so shrinking the drawing shrank the type and it needed a `--topo-w` floor plus a scroll hint. Both are gone: an HTML card's label is page-sized type and truncates with a real ellipsis, and panning is React Flow's rather than a scroll container's. **The frame's height is NOT what sets the opening zoom.** `fitView` takes the smaller of the two axis scales and this graph is laid out left-to-right, so WIDTH binds: raising `.topo-view` from 26/58vh/42 to 34/74vh/58 moved the canvas from 580px to 814px and left the zoom at 0.826 exactly. What moved it to 0.95 was cutting `fitViewOptions.padding` from 0.15 to 0.06 (15% of *each* side is 30% of the frame) and `ranksep` from 96 to 72 — every pixel between ranks is width the whole map is then scaled down to fit. Measure the viewport transform after changing any of the three; do not reason about which one will help. **The wheel is deliberately NOT captured** (`zoomOnScroll={false}`, `preventScrolling={false}`): a map that swallows the scroll traps a reader who is only trying to reach the tables below it. Zoom is `Ctrl`/`Cmd` + scroll, and `zoomActivationKeyCode` names **both** keys — React Flow's default is `Meta` alone, which is nothing at all on Linux, and the legend promises Ctrl.
- **The prompt and skill bodies render as markdown** (`markdown.ts`), where they used to sit in a `<pre>` showing their own asterisks and backticks. It is a SUBSET, sized to what `prompts/` actually contains and counted before a line was written: 124 bullets (one nesting level), 72 bold runs, 52 inline-code spans, 38 headings over three levels, ~45 ordered items, 3 fences — and every pipe-table row already lives inside a fence, so there is no table support and nothing to add until one appears outside one. Hand-rolled rather than a dependency for `rca.ts`'s reason, and the rule that matters is the same one: **esc() first, then markup, never the other way round.** These pages have no `script-src` at all, which is what makes a missed `esc()` inert everywhere else — generating HTML from text is exactly where that stops being free. Deliberately NOT shared with `rca.ts`: that parses Slack mrkdwn, where bold is a single `*` and italics are `_underscores_`, so one renderer for both would get one of them wrong. Three things are load-bearing: **a fenced block is verbatim with no inline markup** (it holds the LogQL and PromQL `skills/real.test.ts` parses and an operator retypes, so an asterisk in one is query text); **inline code is resolved before bold**, because a code span may contain asterisks and the other order eats them; and **headings start at `<h3>`**, since the page already owns `h1` and `h2` and two `h1`s break the sequence a screen reader navigates by — the document's SHALLOWEST heading is the `<h3>` (`system.md` opens at `##`, which rendered as `<h4>` straight under the title), and `docPage`/the postmortem put an `sr-only` `<h2>` before the card so the sequence is h1 → h2 → h3 (UI audit 2026-11-12). The same audit set a 24px floor on small targets (`a.standalone`, eyebrow back-links, skill-card names, every `summary`; padding plus an equal negative margin, so nothing moves) and let the `/cluster` summary's Flux revision break, which held the card 32px past a 390px screen. It renders inside `.card` — the panel the `<pre>` used to give it, reused rather than redescribed, because bare prose on the page background reads as something that fell out of its container. A skill's `when` is NOT markdown and stays in its own `<pre>` — it is a regex read character by character. `markdown.test.ts` renders the real prompt and all 14 shipped skills and asserts every tag balances, which is the only thing that catches a construct nobody anticipated.
  - **`.md` declares NO font size, and that is the point.** It set `--fs-md` (17px), copied from the RCA's prose on the argument that both are long-form text — but the RCA is the whole content of its own page, while this sits in a card among page furniture whose paragraphs are 13px and whose `body` is `--fs-base` (15px). Measured: a 17px block inside a 15px page reads as a different typographic system, which is what a reader reported. Inheriting means it cannot drift from the page again. The one thing it still states is the LEADING (1.7), which a 24,000-character document earns and the page's 1.55 does not give it.
  - **A heading may never be smaller than the body it introduces.** `.md h4` shipped at `--fs-base` under an `--fs-md` body, so every `##` rendered as a heading a reader had to be told was one — the identical mistake the RCA page had already made and written down. It matches the body size now and ranks by weight and space.
- **Dashboard CSP is per route** (`csp(nonce?)` in `src/dashboard/server.ts`). Only the two maps (`/topology`, `/cluster`) pass a nonce, and they are the only pages that get a `script-src`; every other page has none, which is what keeps a missed `esc()` inert where LLM output is rendered. **`style-src 'self' 'unsafe-inline'; font-src 'self'` is on every page since 2026-11-10**, because the stylesheet stopped being inlined and loads the one font. `'self'` used to ride with the nonce only, on the argument that it gives an injected `<link>` somewhere to point — so it is worth being exact about what it can point at: this origin serves CSS from a closed `Map` of content-hashed paths and nothing else, every page is sent `nosniff` as `text/html` so a browser will not apply one as a stylesheet, and nothing a visitor writes is ever stored under `/assets`. `'unsafe-inline'` (styles only) already allowed an injected style attribute; `'self'` adds no file an attacker controls. `/topology` ships **two** tags and the nonce covers both — a tag the header does not name is a tag the browser refuses, which here is an interactive map that silently is not one. Never `'unsafe-inline'` for scripts.
  - **The topology data is a `<script type="application/json">` data block, not a nonce'd block assigning a global.** A data block is never executed and `script-src` does not gate it, so operator-supplied strings cannot become script however they are escaped. The escaping is still mandatory and is `<`/`>`/`&` → `\uXXXX`: a raw `</script>` inside any string closes the element early and drops the rest of the topology into the document AS MARKUP. All three are legal escapes inside a JSON string, so the output stays `JSON.parse`-able with no cooperation from the client.
  - **The map is script-only, and that is a trade this rewrite made deliberately.** The SVG it replaced drew the whole thing with no script at all. The mount now ships one sentence saying so, which `client/topology.tsx` clears on a successful parse — a frame that shipped empty would read as a broken page rather than one that needs JavaScript. The four tables below carry every fact the map draws and are untouched, which is the only reason the map is allowed to degrade to a sentence. `topologyPage(t, nonce, assets, open)` takes `assets: Assets | null`; **null is a supported state** (`npm run dev` never bundles) and renders a note, not a crash.
  - **Every static asset is content-addressed** — the map bundles (`assets.ts` hashes the body into the name, read once at boot) and, since 2026-11-10, the stylesheet and its font (`stylesheet.ts`, same scheme) — and they are **the only responses on this dashboard that are not `no-store`** — a new build is a new URL, so the old one can never come to mean something else. The bundles are served behind the session check; the stylesheet and font before it, because the sign-in page links them. The path is a key into a `Map` of two files, never a filesystem lookup, so there is no traversal to defend against.
  - **Everything else is still script-free and needs no CSP change**: the time range is three links (`?range=`), the segmented control is `aria-current`, and the self-refresh is `<meta http-equiv="refresh">`. The refresh is on the overview always and on `/incidents` **only when nothing is filtered and nothing is paged** — a reader who typed a filter is working, and reloading under them mid-row is worse than a stale page (`views.test.ts` pins both).
- **Postgres and Redis expand into what they HOLD, and both lists are DERIVED rather than transcribed** (`stores.ts`). That distinction is the whole file: a hand-kept list of five tables is correct until migration 008 and then quietly wrong, on a page whose contract is that it reports the process rather than a description of it. Postgres is parsed out of the shipped `migrations/*.sql` — the same files `runMigrations()` applies — with `stores.test.ts` asserting against the real directory and checking every table names a migration that exists. Redis is composed from `REDIS_KEYS` constants owned by `agent/memory` and `agent/dedup`, and `agent/memory/index.test.ts` greps those modules' own source and **fails if a literal prefix reaches a `redis.*()` call without being declared** — verified to bite by planting one. Nothing here probes: no connection is opened and no query is run, same as the rest of the page. Both lists render even when the dependency is **not configured** — the schema is what this agent *would* write, and "where does an incident go" deserves an answer either way. `postgresTables()` is cached because it is called per request and the migrations cannot change while the process lives; an absent directory yields `[]`, which renders a card with nothing to expand rather than an error.
- **Both SQS cards expand into their queues, and the response queue is ONE node with two edges into it.** That is the cross-repo contract drawn rather than written: the LLM path and the GitOps path use a second *request* queue but the **same** response queue, routed by `requestId` (`agent/gitops/sqs.ts` takes `responseQueueName` from `config.llm.sqs`). Two nodes would state the opposite of it, and "there must be two response queues" is the most common wrong assumption about that path — the same class of error as thinking every backend goes through the worker. Sharing is **declared** (`Store.id`, both cards naming `sqs-response`), never inferred from the label: deduping by label would silently merge two dependencies that happen to be spelled alike, and there is a test for exactly that. `buildGraph` guards every `push` with a `seen` set, because a duplicate id is a React key warning and a silently dropped card rather than an error anyone would see. The browser check asserts **two edges terminate at the node**, not just that one node exists — React Flow drops an edge whose endpoints it cannot find, so the node count alone proves nothing.
- **The MAP is Tailwind + shadcn; everything else on the dashboard is not, and the seam is deliberate.** `styles.ts` still owns all seven server-rendered pages and React Flow's own furniture (edges, controls, the dot grid — library-generated classes, so plain CSS is the right tool). The map's CARDS moved to `cva` in `client/card-variants.ts` with vendored shadcn `Badge` and `Button`. Four things make the seam hold, and each one cost something to find:
  - **No preflight.** `tailwind.css` imports `theme.css` and `utilities.css` by hand instead of `@import "tailwindcss"`, because the output is served as `topology.css` — linked in the `<head>` of a page whose tables, rail and chrome are server-rendered. Preflight would strip the margins off every heading and the borders off every table on that same page. **The price is that the UA's own form-control styling is no longer neutralised for us**: the first build shipped every disclosure card wearing a grey `buttonface` box inside a UA border, because shadcn's components assume that reset ran. `bg-transparent border-0 font-[inherit]` on the Button base is that reset, applied where it is needed.
  - **The tokens are ALIASES, not values.** Every shadcn colour name points at the variable the rest of the dashboard already uses, so the map cannot become a grey shadcn island in an indigo page — and dark mode needs no `.dark` class and no variant config at all, because those variables already flip under `prefers-color-scheme` **and** under the reader's `data-theme` choice (the dark block in `styles.ts` covers both). React Flow's OWN chrome does not read those variables, which is what `colorMode={mapColorMode()}` is for. `--color-border` is aliased to **`--mark-line`** and not to `--border`: that one is a decision rather than a mapping, and mapping it the obvious way would quietly undo a contrast fix (3.63:1 against 1.65) that took a round of measuring to find.
  - **Tailwind's utilities are UNLAYERED; only the theme is layered.** An unlayered declaration beats any layered one whatever the specificity, so `@layer utilities` meant every plain rule in `styles.ts` won over every Tailwind class on the map — the seam was losing every contest and it took an underlined card caption to notice (`a { text-decoration: underline }` at 0,0,1 beating `.no-underline` at 0,1,0). Not a source-order problem, and no specificity fixes it. The theme stays layered because it is only variable declarations and *should* lose to anything the page states itself.
  - **`styles.ts` must not still style a card.** It is the dashboard's own stylesheet and is linked LAST in the head (after `topology.css`), so any leftover `.topo-node` rule would beat every shadcn variant and the two systems would fight somewhere nobody thinks to look. There is a test asserting it holds only the frame and the furniture.
  - **Overrides go THROUGH `cn`, plain and last.** The legend resizes a real card to make its swatch; concatenating classes after `cardClass()` leaves both widths and lets source order decide. No important modifier fixes it — measured: Tailwind v4 does not generate the v3 `!w-[22px]` prefix at all, and the v4 `w-[22px]!` suffix makes `twMerge` keep BOTH. Only the unmodified form gets the conflict resolved.
- **The legend moved into the bundle, and that is what KEEPS its rule rather than breaking it.** A swatch must be the same element with the same classes as the thing it explains — it drifted once. A server-rendered legend would now have to hand-copy Tailwind strings out of `nodes.tsx`, which is that same failure with more steps; `client/legend.tsx` calls the same `cardClass()` the cards do. The claims it used to be checked by moved with it: `card-variants.test.ts` runs headless (pure `cva` + `cn`, no React import) and pins the colour discipline — one fill, structure on the mark ramp, state never on colour alone, the agent by weight.
- **Icons are a closed union, not a free-form string** (`IconName`, drawn by `client/icons.tsx`). `buildTopology` naming one is the same kind of explicit act as naming a field, and a name the client has no glyph for is a type error rather than a blank square. Hand-written inline SVG like every other glyph here (`default-src 'none'` blocks icon fonts and sprite `<use>` both), stroke-only on `currentColor`, `aria-hidden` without exception — the card's title already says what it is. **Every card kind carries one**, so the text starts on one left edge across the map — `inbound`/`outbound` from `Node.icon` (a per-dependency choice, named in `buildTopology`), and `agent`/`backend`/`capability` set by kind in `buildGraph`, where there is no per-node choice to make. The glyph sits in the same tinted chip the KPI shelf uses (`.stat .kpi-icon`: `1.875rem`, `--r-sm`, `--brand-tint` behind `--accent`) — the same numbers on purpose, because a second chip that merely resembles it is a second thing to keep in step. **Every width on this map has been paid for by the chip and measured after it**: structural 216 → 240 → 260, capability 150 → 172, backend 190 → 200. Each bump was the amount a real title came up short by, never a round number — the card pays for the icon; the label does not. Long CAPTIONS still truncate and that is correct: the map is the glance, the row below is the record.
- **A tool family expands into child nodes, and the layout is the hard part.** Clicking a capability card toggles it; `buildGraph(topology, expanded)` takes the open set as a PARAMETER rather than the client holding it as private state, because "a tool hangs off the family that exposes it" is a claim and claims belong where `npm test` can reach them. The expansion set is the only state `TopoMap` owns — the graph and the layout are both derived from it, so the two cannot disagree. The mechanism is **generic**: `expanded` is set by `buildGraph` on any card that has children, the client keys its toggle on that field being *set* rather than on the kind, and both leaf kinds (`tool`, `store`) are packed the same way. They stay two kinds rather than one "child" because they are different claims — a tool is something the MCP server said it exposes, a store is something this agent WRITES — and the map says so in two different words and two different borders (a store is solid, a tool is dashed). **Tools are NOT laid out by dagre.** dagre stacks a rank in one column, and `k8s` registers 34 tools: the first build of this produced ~1400px of vertical, pushed the whole map off screen, and a reader who clicked "expand" lost everything. Each open family is handed to dagre as **one synthetic node sized to the whole block**, which reserves the space and keeps every other card clear of it; the tools are dealt into a roughly-square grid inside that reservation afterwards (`gridCols` solves `cols*W == (n/cols)*H`, so the aspect holds at any count). **`fitView` runs after every toggle and not on the first render** — the `fitView` prop already handles the mount and running both fights over the viewport. Without the re-fit the tools land off the right edge and the agent goes off the left; that is measured, not theoretical. Re-laying out **discards a reader's drags**, and that is correct rather than a limitation: opening 34 tools has to make room, and hand-placed cards would either overlap the new nodes or leave a hole where they belong.
- **A family card carries two controls, and they are siblings.** The disclosure took the card's click, so the "every card links to its row" contract needed its own affordance — a `↓` anchor in the corner, which `stopPropagation`s or the family toggles on its way to the row it was asked to open. A `<button>` inside an `<a>` is invalid and either nesting makes one unreachable by keyboard. **A tool node has no `href` at all**: the tables list it inside its family's `<details>`, which has no id, so a link would go nowhere — the legend was reworded rather than kept, since "every card links to its row below" stopped being true.
- **The write marker is the WORD, never a colour.** `--accent` is the SQS hop and `--warning` is not-configured; a third meaning on either makes both ambiguous. Weight and case carry it instead — the same trick `stateBadge()` uses on the incident list.
- **`NODE_SIZE` (`client/layout.ts`) is the box the card is PAINTED INTO, and it clips.** dagre needs a size before React has rendered anything, so it cannot come from measurement — which means the constant and the type scale have to agree, and nothing warns when they stop. `.topo-node` is `overflow: hidden` and centres its content, so content taller than the box loses its top *and* bottom: a backend card at 56px cut the title in half and the caption overlapped what was left. Found by eye in a screenshot, not by a test. A backend is the tall one because it carries three lines — name, model, route chip — and the route is on the **chip only**; stating it in the caption as well is what overflowed it in the first place. `scrollHeight > clientHeight` is the assertion to reach for if this is ever automated.
- **What the tests cover, and what they cannot.** `topology-graph.test.ts` pins the claims, `client/layout.test.ts` runs dagre under `node:test` (it is pure JS; `@xyflow/react` is imported for types only, so the module loads with no DOM) and pins finite positions, the left-to-right reading order, non-overlap (including with a family open), that an expanded family packs into a block rather than a column, and that the `topo-edge-sqs` class lands on exactly the edge that crosses a queue — which is what carries the distinction now that motion is uniform. **React Flow's rendering, the drag behaviour and the CSS all need a browser and are not covered by `npm test`.** Say so rather than reading a green suite as more than it is.
- **`/cluster` is the second React Flow map, and it shares everything but its graph** (spec `docs/superpowers/specs/2026-10-08-cluster-map-design.md`). A second esbuild entry, `cluster.js`, that imports NO stylesheet — the page links `topology.css`, which carries React Flow's stylesheet and the shared Tailwind subset, and the build deletes any `cluster.css` (the FORBIDDEN scan covers both bundles). The page embeds the cached `k8s_cluster_inventory` result as an escaped `application/json` block under the response's nonce, exactly as `/topology` does, and `cluster-graph.ts` — pure, type-only imports from `cluster-types.ts` — builds the graph IN THE CLIENT so expanding a namespace recomputes it without a reload. Every edge is a relation the mcp-server computed (`serves`, `backends`) or `managedBy`; nothing is read off a name. Two layout decisions were measured on the live cluster, not reasoned: collapsed namespaces are a **grid** (4 per row, 2 under a 640px frame) because dagre stacks edgeless nodes in one column — 17 cards opened at scale 0.47, the grid opens at 0.87 — and each expanded namespace is its own dagre block below the grid, so opening one never moves another. The re-fit after a change waits for `useNodesInitialized`: on the next frame (as `/topology` does) React Flow had not measured the new cards and the fit used the old bounds. **An open namespace is a panel with fixed LANES** (Ingress host | Service | Workload | Managed by), one row per workload — the first version let dagre rank each row and a row with no host slid left under the wrong heading, which a reader called dizzying; a card's x is its kind now, and every card in a panel is the same height so a row is one line. Each kind has a glyph and a left accent bar from the mark ramp (managed-by-GitOps ok-green, outside GitOps warning-amber), never colour alone. The panel is TWO nodes: the frame at `zIndex -1` (under the edges, `pointer-events-none`) and a header node above the pane holding the name, the ✕ and the lane headings — a zIndex -1 node sits under React Flow's pane, AND a node that is neither draggable nor selectable gets `pointer-events: none` from React Flow, so the header states `style.pointerEvents: "all"` or its ✕ is unclickable (both found in the browser, both now pinned by a layout test). The open namespace's grid card stays, marked `−`. **Since 2026-11-11 the page is a namespace master–detail and the map draws ONE namespace.** `clusterPage(..., view, ns)` renders a server-side list of every namespace (`nav.ns-list`: Application, then System — the old system-namespaces fold is gone) as links to `?ns=<name>`, and beside it the selected namespace: a summary card, the map, and a Workloads panel sorted not-ready → outside GitOps → the rest, with the Git path from the cluster model's `changeAt` as a `.sub` line under the owner (a sixth column ran off the card). No `ns`, or an unknown one, picks the first application namespace with something to act on — one with a workload short of its count before one merely outside GitOps (it opened on `cloudflared` while `monitoring` was 6/7, 2026-11-12) — and the Not ready tile links to that namespace. The list replaces the map's collapsed-namespace grid, so the mount carries `data-ns` and `client/cluster.tsx` (`only`) filters the inventory to that namespace, opens it, drops its grid card and gives the panel head no ✕; `buildClusterGraph`/`layoutClusterGraph` are unchanged and the grid/expand path below still exists for a mount without `data-ns`. The frame's height follows `--rows` (the workload count, set inline on the mount) because width binds the fit and a fixed-height frame left a three-row namespace floating. Below 62rem of page the list stacks above the detail — the five-column table did not fit beside it at 51rem. An empty namespace renders no map. The paragraphs that follow describe the map's internals, which did not change. Since multi-cluster 2c the page takes `?cluster=<name>` and, in strict mode, a `.seg` switch per cluster; each cluster has its own `ClusterModelCache` and a 10 s inventory timeout so a cluster that is down renders an error instead of hanging the page (agent `CLAUDE.md`, 2c).
- **`/memory` is what the agent remembers, and it reads the agent rather than re-deriving it** (2026-10-20, `memory-views.ts`). Two halves, and they are **two rail destinations, not tabs** — an in-page "By alert | Conversations" switch read badly (feedback 2026-10-20); each page and its detail pages mark their own item. **By alert**: one row per (alertname, namespace) — the key `IncidentMemory.recall()` reads by, top-level incidents only (`TOP_LEVEL`), a remediation counted only once it ran — and a key page whose "What the agent will read" block is the output of the agent's OWN `memoryRecall()` (`recallIncidents` + `recallRemediations`), passed in as `MemorySource.recall`. A dashboard copy of recall would be a second implementation that drifts, on the one page whose claim is "this is what the model reads". The key is query parameters (`/memory/alert?name=&ns=`), never a path, because **no `ns` is the NULL-namespace key** and an absent label must stay distinguishable from any spelling of one; the per-tier source rows match it with `IS NOT DISTINCT FROM`. The "possibly related" tier is full-text on an alert's own text, so it cannot be shown and the page says so. **Conversations**: `ConversationMemory.list()`/`inspect()` (SCAN, never KEYS; capped at 100) — the window the model reads on the thread's next turn, issue pinned at [0], TTL, RCA flag, carried skills. These two routes sit **before the database gate** (Redis or in-process, so they answer while Postgres is down; incident links degrade to none). **Conversation pages (2026-11-11):** a thread is named by the alertname of the incident opened in it (`threadIncidents` returns `{id, alertname, severity, resolved}`; no incident → "Conversation"), both pages take the KPI-shelf/panel shape, the thread page is the `.detail` grid (transcript in the main column, facts + carried skills beside it), the model's text is rendered as Slack mrkdwn through `rca.ts`'s `inlineMrkdwn` (escaped first — before this the RCA showed its raw `*`, `` ` `` and `_`), tool calls and results are one line each with a direction arrow, and a pinned first message over 600 chars folds behind a header naming it. **A tool result is printed as its size and first line, never more** — it is raw cluster output (`k8s_list_configmaps` returns data), and the full record already lives in the trace, which the page links; `memory-views.test.ts` pins that a second line never reaches the HTML. Read-only by type: `MemorySource` has no method that writes.
- **`/people` reads the agent's own access lists, never a copy** (`people-views.ts`). On-call / approver / allowed are `config.slack`'s arrays, the ones `app/remediation.ts` and `slackUserAllowed()` enforce: the approver count applies the same on-call fallback and the mention count is allowed ∪ on-call ∪ approvers, so the KPI shelf and the Access policy table cannot describe a policy the agent is not running (`accessPolicy()` is the one place, tested). Activity is `remediations.approved_by` (written on approve AND reject); a decider on no list is flagged `not listed`, a listed user whose Slack account is gone `deactivated`. Profiles come from `SlackApp.userProfiles` (`users.info`, `users:read`, cached 1h per process; the scope needs an app REINSTALL before the token carries it) and a failed lookup prints its Slack error and falls back to the id. Avatars are initials, not Slack photos — the CSP has no `img-src` for Slack's CDN and a picture is not worth opening one. The ratio bar's track (rejections) is deliberately untoned: a reject is the gate working. It sits before the database gate: the lists are config, so the page answers while Postgres is down. Read-only by design — the dashboard password is shared, and an editable list would let anyone holding it make themselves an approver. The `/people` CSS block (end of `styles/tables.ts`) re-pinned `styles.test.ts`'s length and hash — a new rule does that on purpose.
- **Page shape (the 2026-10-26/27 pass over every page)** — every page now follows it. (0) The head is one `<div class="doc">` holding eyebrow (Monitor or Agent, or a link back to the parent page) + `<h1>` + one meta line that leads with the page's count; laid into `<main>` as loose children, `main > * + *` spaced the title from its own caption like two sections. `.doc > .stats` carries the block gap below a shelf, because a map frame or a fold after it brings no margin of its own. Slack ids anywhere on a page go through `DashboardServer.nameMap()` (the `/people` lookup and cache) and print as name + id, the id alone when no name came back. A page's actions are `.page-actions` buttons (`a.standalone`, one `.primary` at most). A conversation window is a transcript of `.turn` cards, not a table. (1) A page opens with **one KPI shelf** (`statList`, exactly four tiles) answering what a reader opens it for; a tile is toned only when the figure IS bad news, and `delta()` (moved from the overview into `parts.ts`) states movement against the previous period or run, in points for a rate. (2) **Methodology and look-up material fold** into `<details class="fold">` — a reader scans the figures and opens the explanation when needed; `/bench` was 5,000px of prose, cases and eighteen spot checks. A run list keeps the newest `open` and folds the rest to their header (`details.bench-run`: a `<details>` is not a reliable grid container, so the grid sits on the summary and the body). (3) **A number that is a share gets a bar beside it**: `.ratio` (one share), `.stack-bar` + `.stack-legend` (a whole split into parts, every segment named in the legend — never colour alone), `.lat-bar` (p50 head over a p95 run, both against the slowest on the page). A ranking bar carries no tone. (4) **A ranked table on a phone is a two-line row, not a captioned form**: `.bench-table` rows with a `td.rate` go to a grid at 46rem (name across, then bar · counts with inline captions) — the 24-case table went from ~7,900px of stacked captions to one screen of rows. Every new rule re-pins `styles.test.ts`.
